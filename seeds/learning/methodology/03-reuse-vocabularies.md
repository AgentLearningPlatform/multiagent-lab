# 复用既有词表与顶层本体

> 学习中心方法论卡片 · REQ-90 模块三（深度版，v0.2）。

## 为什么复用优先

建模前先找现成词表。复用的收益是**互操作**——你的"组织"与外部世界的"组织"对得上号，Agent 检索时能吃到通用语义；自造词则是一座孤岛。

## 常用词表速查

| 词表 | 领域 | 典型条目 |
| --- | --- | --- |
| FOAF | 人物与组织 | foaf:Person / foaf:Organization / foaf:member |
| SKOS | 分类体系与主题词表 | skos:Concept / skos:broader / skos:prefLabel |
| schema.org | 通用实体 | Person / Organization / Product |
| Dublin Core | 文献元数据 | dc:title / dc:creator / dc:date |
| BFO / DOLCE | 顶层本体 | continuant（持续体）/ occurrent（发生体） |

## 实操建议

1. 自建概念若与词表条目语义一致，用注记（如 `rdfs:seeAlso` 或等价声明）挂接而非重造。
2. 顶层本体不必全盘采用，但"物质/过程""抽象/具体"这类最高层区分值得借鉴——它们决定你的概念树第一层怎么分。
3. 复用不等于照搬：词表里 80% 的条目你用不上，只挂接真正回答 CQ 的那部分。

## 深度版：对齐的工程实践

### 三种挂接强度

1. **注记级**（`rdfs:seeAlso`）：最弱，只是"读者参考"，机器不做任何推断——适合语义只是相近的情况。
2. **等价级**（`owl:equivalentClass`）：最强，推理机会把两侧类视为同一——适合语义完全一致且词表可信的情况。
3. **子类级**（自建概念 ⊑ 词表概念）：中间档，既表达"我的更具体"，又吃到词表的上层语义——**多数场景的最优解**。

选错强度是常见事故：等价声明挂在语义相近但不同的概念上，推理结果会悄悄变错。

### 顶层本体的取舍

BFO/DOLCE 的价值不在条目本身，而在**第一刀怎么切**：continuant（持续存在的东西：设备、人员）/ occurrent（发生的过程：故障、维护）。第一层切对了，后面所有层次都顺；切错了（比如把"故障"既当过程又当状态）越建越乱。不必引入整个顶层本体，但建模前用它的视角自查一遍第一层。

### 反例辨析

- **为复用而复用**：schema.org 的 Person 有 30+ 属性，你的 CQ 只用到姓名——挂接语义即可，别把属性面搬进来。
- **版本漂移**：外部词表会更新，等价声明要跟着维护；注记级无此负担。
- **skos:Concept ≠ owl:Class**：SKOS 管主题词表（分类标签），OWL 管类与推理——"缺陷类型"用 SKOS 分类，"缺陷"本身用 OWL 类，两者别混（设备故障示例的等级字段是 SKOS 化改造的候选）。
