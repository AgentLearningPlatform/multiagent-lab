# 设备故障知识本体 · 建模说明

> 示例本体建模说明（REQ-90 ②）。seed-learning key=failure 一键灌装。

## 背景与目标

演示**概念分类（parents）与归因链建模**：故障不是平铺的实例集合，而是有类别的概念树（故障 ⊃ 过热故障）；归因链「原因 → 引起 → 故障」「原因 → 对应 → 措施」是最典型的领域知识结构。该示例同时是 REQ-96 数据灌装路径与第 5 示例「设备故障知识库→设备故障本体」（REQ-108，随 O13）的对照物——先看手工建模长什么样，再看从知识库自动抽取能到什么程度。

## 目标 CQ 列表

1. 某部件发生过哪些故障？（发生）
2. 某故障的根本原因是什么？（反向：引起）
3. 某原因对应什么维护措施？（对应）
4. 过热类故障有哪些？（**分类推断**：带推理方案下 subClassOf 传导，过热故障实例会以故障类型被查到——与 O6 推理对照实验直接衔接）

## 建模决策记录

| 决策 | 理由 |
| --- | --- |
| 故障设子类「过热故障」（parents） | 演示多继承字段的最小用法；分类是故障知识的核心结构 |
| 引起（原因→故障）方向 | 原因是主语——"散热不良引起过热停机"符合领域叙述；反向查询用 SPARQL 变量翻转即可 |
| 原因与措施用「对应」关系而非合并 | 措施可复用于多原因、原因可有多条措施，多对多必须拆成独立概念 |
| 部件独立于设备 | 设备-部件两级分解让「发生」关系落在部件上，粒度更细 |

## 局限与反例

- **无时间维度**：真实故障知识需要发生时间/持续时长属性，本例省略以保持精简。
- **原因层级未建模**：根因/直接原因的区分可用 parents 或独立关系，留给学习者扩展。
- **等级用字符串属性**：与缺陷示例同样的问题——规范做法是 SKOS 分类（见方法论模块三）。
- **实例名中文**：演示 spec_json 对非 ASCII 名称的兼容；真实工程建议 URI 友好的英文 id + 中文 label。
