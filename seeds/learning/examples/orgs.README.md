# 组织与人员本体 · 建模说明

> 示例本体建模说明（REQ-90 ②）。seed-learning key=orgs 一键灌装。

## 背景与目标

演示**复用路径**（对照 FOAF 术语）与**多层关系建模**：组织→部门→组三层级、人员三向关系（任职于/担任/参与）。对照 FOAF（foaf:Organization / foaf:Person / foaf:currentProject）体会"什么时候复用标准词表、什么时候自建"——本例刻意全自建，学习者可尝试把人员概念映射到 FOAF:Person 作为练习。

## 目标 CQ 列表

1. 某组织下设哪些部门？（下设）
2. 某人员参与了哪些项目？（参与）
3. 某部门承接的项目有哪些人参与？（承接 + 参与 两跳连接）
4. 「组」的实例能否被当作「部门」查询？（**多继承推断**：组 ⊑ 部门，带推理方案下成立——与 O6 推理对照实验直接衔接）

## 建模决策记录

| 决策 | 理由 |
| --- | --- |
| 组 ⊑ 部门（parents 多继承演示） | 组是更小的部门单元——subClassOf 语义自然，且让推理对照有话可说 |
| 任职于指向部门（含组） | 人员实际挂在具体单元上；层级归属靠关系链而非概念树表达 |
| 岗位独立概念而非属性 | 岗位可有多人担任、可继承职责，字符串属性表达不了这种复用 |
| 未复用 FOAF | 教学取舍：先自建理解建模过程，复用对照留作练习（见方法论模块三） |

## 局限与反例

- **无时间区间**：任职/参与都有起止时间，真实 HR 本体需要 n-ary 建模（任职事件作为独立概念）——字符串属性装不下"曾经任职"。
- **下设/内设语义重叠**：组织-部门与部门-组用了两个关系，也可以统一为一个「下设」+ 层级约束；两种做法各有取舍。
- **无人员间关系**：汇报线（reportsTo）是组织本体的核心关系，本例省略。
