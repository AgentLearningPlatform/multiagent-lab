# 平台总览

## 产品定位

「Eino Lab · 多智能体学习平台」——用 Go + CloudWeGo Eino/ADK 亲手搭建的**迷你版 Coze**，定位是**学习平台**，双主线：

- **A 线 · 多智能体工程**：从单 Agent 对话到多 Agent 协作、从纯对话到知识/技能/本体增强、从进程内到沙箱化的渐进式掌握（对应学习目标 LG-1~16）。
- **B 线 · 本体工程**：本体的构建 → 运行 → 使用 → 审计全流程，六条构建路径 + 多引擎运行方案（详见「本体」分类）。

功能为学习服务：每条需求都能对应至少一个学习目标；刻意不做企业级能力（登录/多租户/计费/插件市场）。

## 设计原理

- **配置驱动装配**：模型连接 → 智能体 → 项目三层配置全部存库，每次运行按当前配置动态装配 Eino Agent，改配置下一次运行即生效，无需改代码重启。
- **开源优先**：向量库（Qdrant）、图引擎（Oxigraph/Fuseki）、前端组件（Ant Design 生态）都用现成开源；自研只保留学习价值无可替代的部分（装配层、KG 轻量实现）。
- **可插拔抽象**：Agent 执行后端（inprocess/docker/k8s）、向量存储（Qdrant/SQLite）、本体运行引擎、推理后端（eino-adk/外部 CLI）均为接口先行，实现可替换。
- **过程可观测**：对话的每次工具调用、子 Agent 委派、知识召回、本体查询都以 SSE 事件流入前端时间线，不黑箱。
- **双平面架构**：主平台（:8080）+ 本体构建平面（:8091）+ 本体运行平面（:8090）独立进程，经反向代理与 MCP 对接；一条 `run-dev.sh` 全部拉起。
- **诚实降级**：本体方案未运行、向量库不可用、外部 CLI 缺失时对应功能明确提示并降级，主对话链路不受影响。
