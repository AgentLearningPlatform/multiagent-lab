## 一、定位：报告路线 × 项目语境的映射

报告的核心命题是**记忆系统视角的动态本体**：智能体长期多会话运行中存在"隐式召回失败"（当前提问与早期陈述无词汇重叠时 dense 检索漏召，Recall@10 从 0.61 跌至 0.28），运行时从对话数据自动归纳一张轻量本体图可使检索在概念层运作（Recall@10 0.706、成本较长上下文降 81%）。报告给出三档路线，其**轻量档**（固定种子 schema + 运行时仅实例填充，1-2 人 / 4-6 周）与本项目现状、主人"低侵入"要求精准对位。

**「动态薄本体」= 报告轻量档在 eino-multiagent-lab 的落地形态**：

| 维度 | 含义 | 本项目落点 |
| --- | --- | --- |
| 动态 | 随对话运行持续生长，今天长出来的知识明天 agent 就能查到 | 旁路抽取管线 + Oxigraph 会话图增量写入 |
| 薄 | 种子 schema 固定（5 骨架类）、仅实例填充；向量层/自动门控/bi-temporal 后置（报告轻量档边界） | 最小数据模型（§四）+ 三阶段渐进（§七） |
| 隔离 | 每会话产出进独立 named graph，与主本体物理隔离，可整体摘除 | Oxigraph `GRAPH <…/graph/conv-{id}>` |
| 低侵入 | 对话主链路 0 改动、装配逻辑 0 改动、消息库只读、开关默认关 | 三原则（§五） |

## 三、架构：旁路管线（对话主链路不动）

```
用户 ↔ Eino ADK 对话流（SSE，0 改动）
        └─会话结束事件（stream close / 消息库游标）
   ┌────────▼────────────────────────────────────────┐
   │ 新建① 伴生 worker（Go goroutine 独立模块）        │
   │  游标读未处理消息 → LLM 结构化抽取（REQ-98 代理，  │
   │  复用 lightweight prompt）→ 候选 JSON 落库 pending │
   └────────┬────────────────────────────────────────┘
   ┌────────▼────────────────────────────────────────┐
   │ 新建② 候选确认流（资产栏「伴生候选」页签）          │
   │  人工确认/修订/拒绝 + 矛盾检测 → 合并事务          │
   └────────┬────────────────────────────────────────┘
   ┌────────▼────────────────────────────────────────┐
   │ Oxigraph：SPARQL INSERT GRAPH <…/graph/conv-{id}> │
   │  + PROV-O activity 审计；矛盾旧边 bot:invalidAt    │
   └────────┬────────────────────────────────────────┘
   ├─ REQ-151 facade sparql_query（graph 参数扩展）：
   │    agent 运行时反查伴生图 ←—「动态」价值兑现
   ├─ REQ-154 3d-force-graph：伴生图成长可视化（开关）
   └─ REQ-127~130 KG 增强检索：伴生图并入检索源（Phase 2）
```

## 四、薄本体数据模型

**种子 schema（5 骨架类，一次性预置，薄版不自动生长）**：

```turtle
@prefix bot: <http://eino-lab/ontology/thin/> .
bot:Concept  a owl:Class .   # 概念（领域实体：Pod、HPA、滚动更新…）
bot:Relation a owl:Class .   # 关系陈述
bot:Event    a owl:Class .   # 事件（带时间性动作/变更）
bot:Source   a owl:Class .   # 来源（会话/消息/文档）
bot:Agent    a owl:Class .   # 参与智能体/用户
```

**会话图（named graph 隔离 + 失效化而非删除）**：

```turtle
GRAPH <http://eino-lab/graph/conv-abc123> {
  <…/e1> a bot:Concept ; rdfs:label "Pod 扩容" ;
      bot:extractedFrom <…/msg-42> ; bot:confidence 0.86 ;
      prov:generatedAtTime "2026-09-25T23:00:00Z" ;
      prov:wasGeneratedBy <…/activity-extract-17> .
  <…/e1> bot:relates <…/e2> .
  <…/e0> bot:invalidAt "2026-09-25T23:00:00Z" .  # 矛盾旧边失效化，保留可查历史
}
```

设计要点：①构建平面 spec_json 与主本体 TTL **完全不接触**——伴生图只存在于消费平面（Oxigraph named graph），不产生第二个影子真相源；②三元组自带溯源（extractedFrom/prov:wasGeneratedBy），满足报告"一切提升带溯源"原则；③低置信度候选只进候选表不入图——对齐报告"低置信信息仍可检索但不影响图"的双存储共生原则的薄版近似。

## 五、低侵入三原则（影响面核对）

| 原则 | 措施 | 影响面 |
| --- | --- | --- |
| 旁路管线 | worker 独立 Go 模块，只读消息库+消费会话结束事件，不进 Eino ADK run 链路 | 对话主链路/SSE 契约 **0 改动** |
| 可选开关 | Agent 配置页「伴生本体」开关默认关；开启才触发抽取与伴生图查询 | 运行装配仅配置项增量 |
| 产物独立 | 候选表/会话图/审计独立，`DROP GRAPH` + 清候选表即整体摘除，停开关即静默 | Oxigraph 引擎 0 改动；前端 1 页签+1 开关 |

## 六、报告六大风险 → 薄版对策

| 报告风险 | 薄版对策 |
| --- | --- |
| R1 本体漂移/词表爆炸 | 种子 schema 冻结（5 类），类型发现 Phase 3 前不开放——薄版结构性免疫 |
| R2 三元组幻觉 | LLM 只做候选生成，入图必经人工确认（人即门控）；抽取消耗走 REQ-98 代理可控 |
| R3 冷启动 | 薄版无门控预热问题（人工确认不依赖证据积累）；混合检索兜底天然存在（dense 为主） |
| R4 矛盾与时序 | 矛盾检测入候选确认流（同实体新断言提示冲突）；失效化而非删除 |
| R5 隐私治理 | 伴生图会话级隔离可整体摘除；PROV-O 全程审计；主人数据不出本地 Oxigraph |
| R6 反馈稀疏 | 薄版不依赖反馈信号（人工确认即监督），无此风险 |
