# 本体底层实现原理（代码地图）

> **定位**：本体模块五栏界面（学习中心 / 构建 / 资产 / 运行 / 消费与审计）背后的实现视角汇总。设计口径与架构决策以 [docs/04_本体_方案设计.md](../../../docs/04_本体_方案设计.md) 为权威事实源；模块导读页 [00_本体模块](../00_本体模块.md) 承载产品语义与教学价值；本文回答「这些能力在哪个服务、哪个包、用什么机制实现」。
> **三平面总览**：构建平面 `ontology-service`（:8091）管 spec 资产全生命周期；运行平面 `runtime-manager`（:8090）管引擎与运行方案；消费平面散布在主后端 `backend`（:8080）——KG、审计、伴生本体、对 Agent 的工具装配。前端 `web/src/pages/ontology/` 五栏一一对应。

## 0. UI 栏 ↔ 服务 ↔ 代码入口对照

| 本体构建 | 构建平面 | `/api/ontologies*`（含 build-from-structured）/ `/api/ontology/ontoextend/*` / `/api/ontology-llm/generate` | `BuildPage.tsx` + `OntoChatFlow` / `BuildFromKBFlow` / `OntoExtendFlow` / `CsvIngestPane` |
| 本体资产 | 构建平面 | `/api/ontologies*`（spec/版本/产物/可视化导出） | `AssetsPage.tsx` + `GraphEditor` / `SpecGraph` / `Graph3D` / `WebVowlView` / `VersionDiff` / `SourceView` |

## 1. 数据模型：spec_json 多形态资产（构建平面）

- **存储**：`ontology-service/internal/repo`——SQLite（modernc.org 纯 Go 驱动，零 CGO，D-O15 单机可部署）。**主形态 spec_json**：概念/关系/实例/属性 + 能力问题（CQ），人类可读、可 diff、可校验、可画图。
- **版本**：保存即新版本，历史版本快照可回取（`GET /api/ontologies/{id}/versions/{version}/spec`），diff 统计由 `diffConcepts` 系函数产出（REQ-95，与 toolchain diff 共源）。
- **产物（artifact）**：挂在本体上的附属工件（TTL 导出、质量报告 `quality-report`、LLM 草稿等），可摘除、零新表。
- **导入分层**（`internal/importer`）：spec 无损 / CSV 实例灌装 / GraphML / OWL-RDF 有损导入——「导入即保留原始形态」是硬要求；oo 双轨 TTL 导入走 merge/preview→apply 审查底座（REQ-157），畸形 TTL 缺 rdfs:domain/range 被 strict 结构校验拦截。
- **导出与转换**：spec_json → Turtle 经系统级 Python sidecar（rdflib）完成，无 venv（D-O15）；sidecar 亦承载 owl2vowl 替代品——平台原生 spec→VOWL JSON 导出（`importer/vowljson.go`，REQ-179 WebVOWL 对照修复）。

## 2. 校验与质量管线（构建平面）

- **结构校验只有一条**：`Spec.Validate`——无论表单、画布、LLM 草稿还是导入，全部收敛到同一段校验；图形编辑器（React Flow）数据经适配器转回 spec_json，不另设管线。
- **质量门禁**（`internal/qualitygate`，REQ-171 P1）：11 检查项数据驱动（孤立概念/缺失定义/命名风格/悬空/层级循环/重复命名等），三维评分（完备 .35 + 一致 .45 + 可维护 .20，扣分制 error-10/warning-3/info-1）；`POST /api/ontology/quality/check` 支持 ontology_id（落 artifact）与 spec 内联（修复循环用，不落库）双模式，strict 开关默认宽松（低侵入三原则）。
- **LLM 生成修复环**（`internal/llmcreate`）：生成草稿 → 结构 Validate + 质量门禁双校验源 → 错误级命中回喂修复 ≤3 轮 → 仍未过转人工（设计铁律：LLM 生成必过门禁）。

## 3. 六条构建路径的实现落点（构建平面）

| # | 路径 | 实现包/端点 | 状态 |
| --- | --- | --- | --- |
| 1 | 自定义构建 | 表单向导（S1~S4 四步）+ `llmcreate` 辅助 | ✅ 教学基准 |
| 2 | OntoChat | `internal/ontochat`——服务端 SQLite 持久化（stage/round/messages/context 含 draft_spec，进程重启会话还原）| ◐ 部分可用 |
| 3 | 由知识库构建 | KB 三策略（chunk 池 LLM 抽取 / GraphRAG KG 直转 / 混合）+ `backend/internal/ontobuild`（CSV/JSON 列角色推断→骨架草稿，`/api/ontologies/build-from-structured`）| ◐ 部分可用 |
| 4 | Open Ontologies | 双轨独立集成（M8.5）：oo 原生 MCP `:8092/mcp` 119 工具经 `/api/oo/*` 反代 + TTL 导入走审查底座回流 | ◐ 引导+导入 |

## 4. 运行平面（runtime-manager :8090）

- **构建/运行解耦（D-O1）**：本体仓库是唯一事实源；运行平面启动多套「运行方案」（引擎 + 本体集合 + 端口），方案停止/删除不影响仓库资产；资产保存新版本后需在方案页**显式重载**（刻意保留的教学点）。
- **引擎适配器**（`internal/engine`）：Oxigraph（P1 默认，`data/bin` 一键安装 REQ-146）/ Fuseki（推理对照）。执行方式当前为**进程内子进程**（REQ-146 链路）；docker/k8s 执行方式可插拔已立项（REQ-179/M-O16）未实施——注意与 Agent 执行沙箱（`backend/internal/runtime` 的 docker/k8s pod 后端，REQ-122 族）是两套独立机制。
- **方案管理**（`internal/manager`）：方案 CRUD/启停/健康探测/端口对账复用；引擎二进制缺失时 `/api/engines` 自检显红 + 一键安装（异步任务）。
- **SPARQL 词法门禁**（`internal/facade/sparql.go`）：SELECT-only 白名单（字面量/IRI 不误伤）+ 10s 超时 + limit 50/200 诚实截断——权威语义在这一层，前端工作台与 facade 各自独立实现同口径。

## 5. 对 Agent 的契约：MCP facade 五工具（Q-14 / D-O17 / REQ-151）

`runtime-manager/internal/facade`——tools/list 固定返回 5 个只读 `onto_*` 工具：`get_concept` / `get_instance` / `list_instances` / `neighbors` + `sparql_query`（受控开放查询面）。tools/call 按 ontology_id 路由到所属 running 方案，工具语义翻译为 SPARQL 在引擎执行——**Agent 侧无感运行时差异**（底层换引擎，契约不变；「受控固定工具 vs 任意查询通道」的取舍本身是教学点）。对话侧经「本体」chip 选 running 方案（存 runtime_profile_id），方案停止明确降级不影响普通对话；onto_* 调用翻译后的 SPARQL 与耗时可在运行方案调试面板透视（REQ-94）。

## 6. 消费与审计（主后端自研）

- **自研轻量 KG**（D-O15 反转的产物）：`backend/internal/store/kg.go` SQLite 三表（kg_entity / kg_relation / kg_claim，claim 带 chunk_id 溯源）+ `backend/internal/kg`（抽取 60 chunks/24k 字符教学口径、label propagation 社区）+ `backend/internal/kb/graphrag.go`（三步检索：向量命中 → KG 一跳扩展 → 关系与 claims 汇出；KG 空回退纯向量标记 degraded）。知识库侧 GraphRAG 与本侧共用这套 KG；其六环节升级规划见调研预研 35 号（KB-4~9 待拍板）。
- **审计**：Agent 本体查询落决策审计表——`/api/audit/decisions`（+ `/chain` 决策链 Timeline、`/prov-export` PROV-O 导出，Go 原生 Turtle 模板零 Python 依赖），回答「这条知识/这次结论从哪来」。
- **伴生本体**（REQ-170，默认关）：`backend/internal/companion`——worker 收尾非阻塞抽取（游标续抽）→ 候选人工确认 → 独立 Oxigraph 实例（`data/companion-graph/` :9199 懒启动，与运行方案动态端口 9201+ 错开）named graph 会话图隔离；**矛盾旧边 bot:invalidAt 失效化而非删除**（图可回溯）；`retrieval.go` 对话召回（标签双向包含匹配 → 实体定义与活跃关系边 → System 注入 + retrieval 事件）。Agent 侧入口见智能体模块 REQ-187/189。

## 7. 前端组件地图（web/src/pages/ontology/）

- **五栏骨架**：`OntologyModule.tsx` 路由 + 五个 Page；BuildPage 为「左路径导航 + 右工作区」两栏（REQ-183），LearnPage 为「左子模块导航 + 右内容区」两栏（REQ-182）。
- **画布三视图**：GraphEditor（React Flow 编辑态，概念/实例双类节点 + RJSF 属性表单）/ SpecGraph（2D 浏览态）/ Graph3D（3d-force-graph 三维，图例驱动显隐·渐进浏览·暗色主题，选型见 [36_本体可视化选型与实现](../03_资产/36_本体可视化选型与实现.md)）+ WebVowlView（webvowl.js 对照，`?format=vowljson` 原生导出供数）。
- **资产工作区**：JsonEditor（CodeMirror JSON，显式所有权同步）/ VersionDiff（结构统计 + 文本对照 react-diff-viewer）/ SourceView（TTL 源码只读）/ SparqlWorkbench（CM6 SPARQL + 模板 + CSV 导出）。
- **共享底座**：LoadErrorAlert（可重试错误卡）/ AIOptimizeButton（REQ-167）。

## 8. 横切约束

1. **零 Python venv（D-O15）**：sidecar 走系统级 python3 + rdflib（`SIDECAR_PYTHON` 可指路）；一切依赖纯 Go 或系统命令（kubectl/docker CLI 同口径）。
2. **单机可部署**：三服务 + SQLite + 内嵌/单二进制引擎，`run-dev.sh` 一条命令。
3. **诚实边界**：KG 抽取/消歧等能力为教学口径的轻量实现，界面与文档如实标注；升级路线见调研预研 35 号。
4. **低侵入三原则**（REQ-171 确立）：端点可独立调用、artifact 可摘除、strict 默认宽松——后续能力扩展沿用。
