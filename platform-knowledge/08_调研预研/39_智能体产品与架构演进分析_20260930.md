## 3. 演进路线建议（E1~E6）

### E1 Agent 评估与质量门控（eval-first）——建议 P1，新立项
治 P-1（+反哺 A-2：给事件契约一个重度消费方）。**最小闭环**：①种子任务集（复用 smoke/ 真机场景 + KB-14 基准先例，build tag 手动跑分器）；②LLM Judge 三值打分（匿名 A/B，与 REQ-207 本体侧门控同构、共享 Judge 基建）；③轨迹回归（吃 run_event：断言工具调用序列/警告数/终态）；④配置 A/B 对照（两份 agent 配置跑同任务集出 diff 报告）。价值：把「改了之后更好吗」从手感变成数据，是配置治理（P-2）与提示词迭代的前置护栏。

### E2 多 Agent 编排收口——P1~P2，以领取在册 REQ 为主
REQ-208 continuation 领取（后台委派+steer+冷恢复，触发条件已近成熟）+ **transfer 治理定案**（存量 collab_mode=transfer 迁移 agent_as_tool，或保留对照+UI 风险标注——44 号 NOT RECOMMENDED 不能只在文档里）+ REQ-205 触发评估（M38/M39 已落地，「跑到哪/崩了重跑」的产品答案随 REQ-217 轨迹面板就位，D 阶段触发条件接近成熟）。治 P-3/A-3。

### E3 会话状态机与事件契约治理——P2，工程收口
统一 interrupt/context/todo/schedule 为会话状态族（状态机抽象+变更留痕）；C5 调度持久化（重启失效补齐）；结构化审计事件（approval.granted/denied、hook.denied 入 run_event）+ data 契约增 schema_version 字段（只增不改）。治 A-1/A-2。

### E4 沙箱执行纵深——P2，触发驱动
work_dir volume 绑定（docker -v / k8s PVC）+ run_command 接线评估（三前置核查：沙箱✅绑定目录→REQ-218 联动后✅审批✅）+ 出网策略。与 REQ-218 文件视图形成「文件可见→文件可执行」闭环。治 A-4。触发条件：出现真实「让 Agent 跑命令/改代码并验证」的本地任务诉求。

### E5 配置治理与工作记忆——P2~P3
Agent 配置版本/草稿出池（改配置可回滚、对话级临时覆盖产品化，治 P-2）；跨会话工作记忆最小形态评估（会话摘要注入 vs 归伴生本体，先划界再立项——D-O19 不混排）。治 P-5/A-8。

### E6 推理后端对等收口——P2，以领取为主
REQ-206 S1~S3 领取（ACP 主通道四项翻正+S3 审计）；能力矩阵「对等路线图」一页化（哪些能力永远 CLI 侧不做、哪些待 S2 翻正）。治 A-5/A-6 部分。**（2026-09-30 晚间状态注：M41 S1+S2 通道面已按排期交付**——streamingProc 长驻基座+acpAdapter 注册，stub ACP agent 驱动验证，session/resume 客户端面翻正；真机 dsh 装机联调四项（真 GLM 工具事件/会话延续语义/MCP http 挂载/权限转审批）+S3 SDK 审计待领取——A-5 缓解过半，余项集中真机联调而非协议开发。）

### 建议节奏
**E1 新立项优先**（最大空白、趋势正确、与 REQ-207 共享 Judge 基建边际成本低）→ E2 领取 REQ-208+transfer 定案 → E3/E6 工程收口随批 → E4/E5 触发驱动。E1/E2 完成后 Agent 侧具备「行为可评、编排可控」两个底座，再谈 E5 记忆与自动化循环（REQ-207 联动）。
