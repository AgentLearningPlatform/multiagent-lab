## 0. 体检基线（已就绪面）

**已交付能力**：绑定本体（选择/创建空本体，迁移 031）→ 旁路抽取（分窗≤16条×≤8k、实体对齐清单、领域聚焦提示、阈值自动入图）→ 候选确认流（三桶/按实体归组/批量/双入口：侧板+资产详情页）→ 本体伴生子图（ont-{id} named graph，矛盾失效化+语义矛盾二分类）→ 持久化（结果集快照+方案重建回灌，真机验证）→ 引擎归一运行平面（宿主方案三段式确保+读侧兜底拉起+单飞化）→ 召回（词法双向包含+向量臂〔依赖 embedding 配置〕+2 跳邻域限流）→ 成长图 3D 四形态入口 → facade sparql_query graph=companion → 审计动作生命周期保护（本体删除 409/agent 级联/解绑语义）。
**真机已验证**：真实 LLM 全链（抽取→确认→跨会话 retrieval 注入）、快照重建回灌、宿主方案自动创建与拉起。

## 1. 产品设计不足（用户视角）

| # | 不足 | 证据 | 严重度 |
|---|---|---|---|
| P-1 | **置信度未校准，自动入图阈值形同虚设**——候选 confidence 是 LLM 自评（本轮真机两候选均 1.0，GLM 自评普遍虚高）；companion_auto_threshold 建立在未校准自评上，>0 的自动入图无质量控制意义 | service.go extractOut.Confidence 直落库；真机 smoke/req216-b3/ 同日证据 | 中 |
| P-2 | **重复确认=覆盖而非聚合，多源印证信号丢失**——同事实（同主体+同关系名）再次 confirm 时 FindActiveEdge 无条件失效化旧边（不比较 object 是否相同），共享本体下多 agent 各自确认同一事实，图里只剩最后一条边，「被几个会话印证过」这一最有价值的可信信号没有承载 | service.go ConfirmCandidate 关系分支（InvalidateEdge 无 object 比较）；候选表有数据（COUNT 可派生）但图与 UI 均未呈现 | 中高 |
| P-3 | **召回效果不可观测**——retrieval 事件有 source/match，但「召回是否实质影响了回答」无追踪：无 hit→回答引用关联、无用户反馈钩子。伴生核心卖点是「沉淀反哺对话」，价值回路整体黑盒 | retrieval 事件字段（entityDetails）；run_event 无伴生命中消费记录 | 中高 |
| P-4 | **知识生命周期只有「失效」没有「过期与消歧」**——①事件类知识（「2026-09 完成灰度切换」）无时效语义，图里永久活跃（REQ-194 批次三 bi-temporal 降级后置）；②同名异义无消歧（对齐清单只防同义异名，slug 归并把「部署」的 K8s 语义与日常语义撞为同一实体） | sparql.go Slug 归并口径；align.go markAligned 仅名称命中 | 中 |
| P-5 | **一 agent 一绑定的路由缺失**——按领域分桶沉淀（K8s 知识入 A 本体、业务知识入 B 本体）做不到：companion_ontology_id 单值，领域聚焦提示词只是抽取过滤不是路由；换绑语义未定案（解绑清游标→绑新本体后下次收尾全量重抽该会话→同事实重复候选涌现，行为未定义） | store.Agent.CompanionOntologyID 单值；service.go ResetAgent 清游标 | 中 |
| P-6 | **伴生型本体在资产页是「空壳资产」+候选无触达**——纯伴生本体详情页 8 页签中 7 个空壳（Spec/校验/版本/产物全空），无差异化呈现；候选产生→确认之间无通知链路（run.finished 不带伴生信息、无侧板红点联动），用户不知道「这次对话沉淀了 3 条待确认」 | AssetsPage Tabs 结构；runConversation emit 不含伴生事件 | 低中 |

## 2. 架构设计不足（实现视角）

| # | 不足 | 证据 | 严重度 |
|---|---|---|---|
| A-1 | **三元组事实源三处无对账**——引擎 named graph / 快照文件 / SQLite 候选表三者一致性靠写路径顺序保证，无校验和与对账；快照损坏（JSON 截断）时 parseTriples 失败**静默不回灌**，图空着且用户无感知（复查轮已知窗口的邻接缺陷） | snapshot.go ensureInflated（perr 静默跳过）；无对账/告警机制 | 中 |
| A-2 | **抽取管线是单次 LLM 调用的薄实现**——单 prompt 无自检修正、无 few-shot、无类型约束；窗口间实体注册表只含图内已有+前窗产物，无会话级全局实体注册；对齐仅名称层（slug），语义层同义异名防不住（「HPA 调整」vs「副本伸缩」会被当两个实体） | service.go ExtractNew；align.go buildAlignmentSection | 中 |
| A-3 | **检索链路工程纵深不足**——①词法臂 O(标签数) 双向包含且 SelectLabels LIMIT 200，标签超 200 静默漏召回；②向量缓存进程内 map 重启全冷，无持久化（KB 侧向量体系不共享——两套基础设施并存）；③2 跳 UNION 查询 ORDER BY hop 后无置信/度数排序，截 8 边可能截掉高价值边；④FTS5（KB 已有）未复用 | sparql.go SelectLabels LIMIT 200；retrieval.go vecCache/maxEntityEdges | 中 |
| A-4 | **治理动作零审计事件**——confirm/reject/reset/unbind 不落 onto_decision（第五栏审计表）也无伴生专属事件表，全程仅日志；收尾抽取过程（窗口数/LLM 调用/对齐清单规模）不可观测（run_event 是 run 维度，抽取在 run 之外） | ConfirmCandidate/ResetAgent 全链；与 39 号 A-2（事件契约未治理）同型 | 中 |
| A-5 | **单实例假设未显式声明**——running 去重 map、单飞锁、快照、vecCache 全为进程内态；多副本部署会同本体双写图冲突。单机定位内可接受，但架构文档无显式边界标注（部署演进时的隐雷） | service.go/plan.go 进程内态 | 低 |
| A-6 | **fuseki 兼容面未验**——SPARQL 写法标准但大批量 INSERT DATA、COUNT(*) 探针、named graph 语义在 fuseki 未实测（快照回灌探针依赖 COUNT 绑定名 n 的解析）；宿主方案默认 oxigraph，fuseki 留可选但切换即未验区 | plan.go countGraphTriples；本机无 fuseki（边界注记维持） | 低 |

## 3. 演进路线（建议，待拍板）

### E1 治理与质量（P1——伴生可信度的根基）
①**印证聚合替代覆盖**：confirm 前查同 slug+同 relName+同 object 活跃边，存在则不新建边、递增候选表的「印证计数」并刷新边 provenance（bot:confirmedBy 多值/bot:confirmCount），图与成长图节点大小/边粗细呈现印证度——P-2 根治；
②**置信校准**：自评置信降级为参考列，自动入图门控改「相对分位（会话内归一化）」或接入 Judge 二值信号（与 REQ-207 配对门控、39 号 E1 共享 Judge 基建——D-O19 不混排指数据面，判官基建共享是另一层，需拍板边界）——P-1 根治；
③**审计事件**：companion 决策落 onto_decision（复用第五栏审计表+溯源链，零新表）——A-4 一半根治。
预估 2~3 人日；验收：同事实两 agent 先后确认图内单边且 confirmCount=2；审计页可见伴生决策行。

### E2 召回价值闭环（P2）
①**命中消费追踪**：retrieval 命中实体在 assistant 回答中词面出现（或模型显式引用）即记 hit，落 run_event（轻量，不引入归因重活）——P-3 最小闭环，先让价值可观测再谈优化；
②**词法臂升级**：复用 KB FTS5 建伴生标签倒排（或标签持久化向量表），解除 LIMIT 200 漏召回与重启全冷；
③**基准进冒烟**：embedding 配置后跑 evaldata 三臂对比，数字入 S4.34 检查行（护栏化）。
预估 1.5~2 人日；验收：命中实体在回答出现时 run_event 可查 hit 记录。

### E3 生命周期与消歧（P2）
①**同名异义消歧建议**：复用 KB-7 双臂模式（规则+向量，kb/disambig.go 直接搬）做 confirm 前同名冲突提醒（不阻断，橙徽标同 REQ-194⑤ 疑似矛盾形态）——P-4②；
②**时效最小版**：抽取 prompt 增「时效性」字段（event 类默认带过期语义），图内 bot:expiresHint 只读呈现，不做自动失效（bi-temporal 仍后置，取其最小可用切片）——P-4①；
③**换绑语义定案**：换绑不清游标改「游标随解绑保留、绑定时提示是否重抽」或显式「全量重沉淀」按钮（二选一拍板）——P-5 后半。
预估 2 人日。

### E4 产品化补全（P2~P3）
①候选触达：run.finished 事件附 companion 增量计数（SSE 契约只增不改）+侧板 activity bar 红点（pending_count 已有数据面）；②伴生型本体详情页差异化（Spec 空态引导「对话生长型本体」+伴生候选设为默认页签）；③成长图时间轴回放（created_at 已在数据面）；④解绑确认弹窗（顺延中）+多本体绑定路由（领域路由，观察项——抽取时 LLM 从绑定集合中选桶，一期可不做）。
预估 2~2.5 人日。

### E5 基础设施与边界（P3，随平台线）
①快照对账：快照文件带三元组计数校验头，损坏告警+从候选表标记异常（A-1）；②抽取可观测：收尾抽取写伴生 worker 事件（debug 面板可见）；③单实例假设显式入 16 号部署文档边界节；④fuseki 真机验证（装机后宿主方案 fuseki 档跑通快照回灌）。
