# 13 · 部署与运行指南

> 状态：v0.1 · 2026-09-21
> 性质：运行/部署事实源。本地开发、服务器部署（Docker Compose）、K8s（Helm）、客户端打包四条路径。
> 环境变量以各服务 `cmd/*/main.go` 实际代码为准（本文已核对）。

## 1. 依赖矩阵与拓扑

| 服务 | 语言 | 端口 | 运行时依赖 | 数据 |
| --- | --- | --- | --- | --- |
| backend（主平台） | Go | :8080 | 无（前端静态托管内置，`WEB_DIST`） | `DB_PATH` SQLite、`SECRET_KEY_FILE`、`FILES_ROOT` 项目文件 |
| ontology-service（构建平面） | Go + **Python sidecar** | :8091 | **python3 + rdflib**（OWL/TTL 导入导出） | `DB_PATH` SQLite、导入工件 |
| runtime-manager（运行平面） | Go | :8090 | **oxigraph_server** 二进制（方案启动时拉起子进程，端口 9201+ 动态分配） | `DB_PATH` SQLite、`ENGINE_DATA_DIR`、`ENGINE_LOG_DIR` |
| agentd（沙箱镜像） | Go | 容器内 | 无（Eino 编译进二进制；启动时凭 `MANIFEST_TOKEN` 向主平台拉配置） | 无（无状态） |
| qdrant（可选） | Rust | :6333 | 官方镜像 | 向量数据 |
| open-ontologies（P2，规划） | **Rust** | :8092 | oo-worker 托管单二进制（pin 版本） | TTL 数据目录 |

- **Rust 现状**：仓库内暂无 Rust 代码。Rust 出现在两处规划面：① open-ontologies（P2，oo-worker 托管其单二进制）；② 客户端打包的 Tauri 方案（§6）。
- **Python 现状**：仅 `tools/rdf-sidecar/sidecar.py`，由 ontology-service 以 `SIDECAR_PYTHON sidecar.py parse|export …` 子进程调用。

## 2. 本地开发

```bash
# 一次性依赖
#   Go 1.25+（go.work 多模块）
#   Node 18+（web/.npmrc 已指向 npmmirror）
#   python3 + rdflib      → pip3 install rdflib -i https://pypi.tuna.tsinghua.edu.cn/simple
#                           （PEP 668 系统拦截时加 --break-system-packages，或建 venv 后设 SIDECAR_PYTHON）
#   oxigraph（0.5+ 改名，旧名 oxigraph_server）→ 方案启动(start)需要。
#   一键安装（x86_64，run-dev.sh 会自动探测 tools/bin/oxigraph 并注入 OXIGRAPH_BIN）：
#     mkdir -p tools/bin && curl -fsSL https://github.com/oxigraph/oxigraph/releases/download/v0.5.11/oxigraph_v0.5.11_x86_64_linux_gnu -o tools/bin/oxigraph && chmod +x tools/bin/oxigraph
#   （aarch64 换 oxigraph_v0.5.11_aarch64_linux_gnu；二进制为 glibc 链接，需 glibc ≥ 2.28；
#     旧版命名 oxigraph_server ≤0.3 兼容，放 data/bin/oxigraph_server 亦可）
./run-dev.sh             # 一键：构建前端 dist（过期自动重建）+ 拉起 backend/:8080 + :8091 + :8090
./run-dev.sh 9090        # 换端口
```

- 缺 python3/rdflib/oxigraph_server **不阻塞启动**，仅对应能力降级（run-dev.sh 会打印警告）。
- 前端热更新：`cd web && npm run dev`（:5173 代理到 :8080）。
- 数据库重置：停服后删 `backend/data/`（清空全部对话与配置）。

## 3. 服务器部署（Docker Compose，推荐起步）

```bash
cd deploy
docker compose up -d --build          # 首次构建较慢（Go/Node 模块下载走国内镜像）
docker compose --profile qdrant up -d # 需要知识库向量检索时加挂 qdrant
# 访问 http://<host>:8080
```

- 三个服务镜像均多阶段构建（见各 `Dockerfile`）；backend 镜像内已烘焙前端产物，单进程对外。
- 数据持久化：`platform-data`（backend）、`ontology-data`、`runtime-data`（含 oxigraph 引擎数据与日志）三个卷。
- 服务间编址（容器网络内）：backend → `ontology-service:8091` / `runtime-manager:8090`；ontology-service → `backend:8080`（ai-draft 用）。
- **沙箱说明**：Docker 沙箱执行（SANDBOX_IMAGE）默认关闭；启用需让 backend 容器可访问 Docker 守护进程（挂载 `/var/run/docker.sock` + `PLATFORM_URL_EXTERNAL=http://<宿主IP>:8080`），属进阶配置。

## 4. Kubernetes（Helm）

```bash
helm install eino-lab deploy/helm/eino-lab -n eino-lab --create-namespace
# 常用覆盖：helm install eino-lab deploy/helm/eino-lab --set ingress.enabled=true --set qdrant.enabled=true
```

- 三个 Deployment + Service（backend/ontology-service/runtime-manager），各自独立 PVC。
- Ingress 可选（默认关），对外仅暴露 backend :8080。
- **已知边界（诚实声明）**：
  1. **oxigraph 动态端口**：runtime-manager 在**本 Pod 内**拉起 oxigraph 子进程（9201+ 端口），SPARQL 端点仅 Pod 内可达——对话/本体查询经 manager 内部转发，功能完整；如需从集群外直连 SPARQL，需自建 hostPort/NodePort 方案（未内置）。
  2. **Docker 沙箱**：K8s 内启用需 DinD 或宿主 docker.sock 挂载（values `sandbox.enabled`，默认 false）；更 K8s 原生的 Pod 后端在 02 §6.3 规划（P2）。
  3. **单副本约束**：三服务均为 SQLite 单文件存储，`replicaCount` 必须为 1（多副本需换存储，超出当前学习定位）。

## 6. 客户端打包（后期选项）

前端为纯 SPA + 本地 Go 服务，客户端化有三条路径（按推荐序）：

1. **Tauri 2（推荐，引入 Rust 工具链）**：Tauri 壳加载打包后的 SPA；三个 Go 服务 + sidecar 作为 **sidecar 进程**随应用分发（Tauri 原生支持 externalBin）。产物单安装包；Rust 仅用于壳，不侵入业务。代价：引入 Rust 工具链 + 三平台交叉编译矩阵。
2. **Electron**：生态最熟、无 Rust，但体积与内存代价大；与"开源优先、避免重壳"的项目基调不符。
3. **纯服务端 + PWA**：不打包客户端，浏览器访问自建服务（即 §3/§4 形态）；零额外成本，"客户端"体验最弱。

> 结论建议：学习/自用阶段维持 §3 Compose 形态；确有离线单机分发需求时再启动 Tauri 方案（届时 Rust 工具链仅服务于壳与 oo-worker，与主业务解耦）。

## 8. 健康检查与排障

- `GET :8080/healthz`（主平台）、`:8091/healthz`（纯文本 ok）、`:8090/healthz`（含 profiles 状态汇总）。
- 常见故障：
  - 本体导入/导出报 sidecar 错 → 容器内 `python3 -c "import rdflib"` 验证（镜像已内置则查挂载覆盖）。
  - 方案启动失败 → runtime-manager 日志 + `last_error` 字段；oxigraph 二进制缺失/端口占用是高频原因。
  - 前端白屏 → backend 日志查 `WEB_DIST` 路径；镜像内路径为 `/app/web/dist`。
