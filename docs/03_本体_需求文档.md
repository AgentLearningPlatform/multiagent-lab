## 0. 背景与目标

eino-multiagent-lab 是学习型 Web 平台，功能分**智能体**与**本体**两类。本体模块目标：支持**导入、创建、编辑、浏览**多个本体，并以后台**多套运行方案**的形式运行本体，供智能体对话结构化查询。

两条架构级原则（主人 2026-09-20 拍板）：

1. **构建与运行解耦**：本体仓库是唯一事实源；运行平面支持同时启动多套本体运行方案，方案停止/删除不影响仓库资产。
2. **开源优先**：各子系统优先使用现成开源方案，避免重复造轮子；自研边界由方案文档 §6 明确。

## 2. 功能需求

### 2.1 本体资产管理（构建平面 · 仓库）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-60 | **本体列表页（类知识库形态）**：列出全部本体（名称、简介、概念/关系/实例统计、版本、更新时间）；支持查询搜索、新建（名称+简介）、重命名、删除（二次确认）；本体为全局资源，可被任意对话的运行方案加载 | P1 |
| REQ-80 | **导入外部本体并直接加载运行**：①支持上传/粘贴外部文件，格式分层：`spec`（自家格式，无损）/ `csv`（nodes+edges 两表）/ `graphml`（通用图交换）/ **OWL-RDF/Turtle（有损导入，P1）**；②导入产生**多形态资产**——原始文件原样存档 + 归一化 spec_json + 导入报告（统计/warnings/有损映射说明）；③导入成功的本体立即可被任意运行方案加载运行 | P1 |
| REQ-69 | **OWL/RDF 有损导入映射**（REQ-80 的 OWL 分支细则）：`rdfs:label`→名称、`rdfs:subClassOf`→继承关系、`owl:NamedIndividual`+`rdf:type`→实例、对象属性断言→实例关系；公理/推理语义丢弃并计入导入报告；映射细则用 ontologies/ 三个真实本体（K8s/FLUIDOS/HOCC）验证后定稿 | P1（v0.5 时为 P2，随 REQ-80 提级） |

| REQ-62 | **内置示例本体**：一个最小 K8s 运维本体（Pod/Node/Service 概念、belongsTo/exposes 关系、若干实例），seed 方式提供，便于上手 | P1 |

| — | **导出**：本体可导出为 spec_json（备份/分享）；RDF 型本体可导出原始形态；**从零创建的本体（仅有 spec_json）可经 spec_json→Turtle 转换导出 RDF 形态**，使其可在 SPARQL 型运行方案中加载运行 | P1（转换器随 O1 交付，由 Python rdflib sidecar 实现——v0.4） |

### 2.4 本体运行方案（运行平面）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-84 | **运行方案管理界面（列表）**：列出所有后台运行方案——名称、运行时类型、已加载本体、状态（running/stopped/error 等）、端口/端点、健康信息；支持启动/停止/删除（二次确认）；状态自动刷新；可查看方案最近日志 | P1 |

| REQ-86 | **多套运行方案并存**：后台可同时运行 ≥2 套方案（不同类型/不同本体集合/不同端口），互不干扰；不同对话可分别挂载不同方案 | P1 |

| REQ-88 | **开源优先原则**（v0.4 调整）：每个子系统先评估开源方案再决定自研；自研仅限业务编排与路由薄层（运行方案编排层、MCP facade 路由）；**OWL/RDF 解析不自研（Python rdflib sidecar）、内存图引擎不自研（P2 直接集成开源）**——清单由方案文档 §6 维护 | P1（原则） |
