## 1. 原型定位

- **目的**：以可点击的静态原型确认界面信息架构与交互流，不涉及视觉稿级别的还原，不含真实后端。
- **形式**：单文件 HTML（无外部依赖），顶部导航切换五大模块；对话可"发送"模拟消息，SSE 事件流可"重放"。
- **演示数据**：均为 mock（Pod 排查、巡检、流水线进度等），字段与产品语言取自 PRD / 技术方案，不代表真实数据。

## 2. 整体信息架构（v0.2 核心变更）

```
顶栏导航：Agent | 项目 | 本体 | 知识库 | 技能     （点击切换下方主界面）
        └─ logo + 原型版本徽标
```

- v0.1 的左侧栏模块导航（含独立"对话"入口、顶栏项目下拉）**取消**，配置类模块全部上移到顶部导航。
- 每个模块统一为 **左列表 + 右详情/工作区** 的两栏布局；窄屏自动改为上下布局（列表横向滚动）。

## 3. 各界面布局与交互

### 3.1 Agent（对应修改思路 ②）

- **左栏**：Agent 列表，每个 Agent 为可折叠节点（`details`）：
  - 展开后列出该 Agent 的全部**对话**，点击对话 → 右侧加载该对话窗口；
  - 每个 Agent 节点提供 **＋新对话** 与 **齿轮配置入口**（打开 Agent 配置抽屉）。
- **右栏**：选中 Agent + 对话后的对话窗口，包含：
  - 配置条：模型来源徽标、**本体运行方案下拉**（仅列出 `running` 状态的方案，draft 禁选——对应 PRD FR-11 与 04 文档 O-6）、已挂技能 chips；
  - 消息流 + **SSE 事件卡**（左侧色条区分来源：技能/内置/MCP/本体），演示一次完整执行链：技能加载 → MCP 工具调用 → 知识库检索 → 本体查询（via mcp）→ 引用回复 → 文件落盘；
  - **降级演示**：切换到不可用的本体方案时展示 `ontology.unavailable` 事件卡（单次失败即降级，配置保留）；
  - 输入区（Enter 发送，模拟回复）；**项目文件面板**（可收起）。
- **Agent 配置抽屉**（dialog）：基本信息 / 模型跟随或独立覆盖（联动详情）/ 技能多选挂载 / MCP 多服务器（工具名加 server 前缀）/ 执行后端三选一（inprocess / docker / k8s，选择后展示对应资源详情）。

### 3.2 项目（对应修改思路 ③）

- **左栏**：项目列表（同样可折叠），每个项目下可 **创建多个对话**；
- **右栏**：选中项目的会话界面，**风格与 Agent 对话界面完全一致**（同一套 CSS/组件）；头部注明"项目：xxx · 会话使用的 Agent：xxx"。
- 演示数据：K8s 运维平台（2 会话）、本体学习实验室（1 会话）；其中"Pod 异常排查"会话与 Agent 视图同一对话在两个入口打开，说明同一对话可在 Agent 视图与项目视图间互通。

### 3.3 本体（对应修改思路 ④，依据 04_本体_方案设计.md v0.4）

- **左栏**：**本体流水线列表**——每个本体从创建到对接 Agent 是一条流水线，条目显示阶段进度（如 7/7）与状态（running / draft / 导入中）。
- **右栏**：选中流水线后展示 **七阶段步骤条（S1~S7）+ 阶段配置卡**，每阶段可点击切换，右上角标注执行模式（builtin / guided / managed）：

| 阶段 | 界面呈现 | 方案依据 |
| --- | --- | --- |
| S1 本体来源 | 导入（多形态资产：original 原样存档 + spec_json 归一化 + 导入报告）/ AI 创建 / 手动 JSON / 内置示例 | §3.1 构建平面 |
| S2 编辑 | JSON 编辑器（P0）/ 图形化（P1 React Flow）；保存后 memory_graph 方案自动生效、RDF 型需手动重载 | §3.2 |
| S3 校验 | JSON Schema + 引用完整性，就地展示通过/错误 | §3.3 |
| S4 可视化 | WebVOWL（TBox）+ 概念链示意图；按运行方案类型路由 ABox 浏览（OntologyExplorer / LodLive） | §3.4 |
| S5 运行方式 | 运行方案卡片（内存图 / Oxigraph / Fuseki，各带状态机 created→starting→running⇄stopped→error 与端口）；新建方案表单（引擎下拉 + 名称）；**managed**：Runtime Manager 编排 | §4 运行平面 |
| S6 对外暴露 | 统一 MCP facade 端点（`/mcp`）+ **4 个固定签名工具**：`onto_get_concept` / `onto_get_instance` / `onto_list_instances` / `onto_neighbors`，按 ontology_id 路由 | §4.4 |
| S7 对接 Agent | 对话挂载运行方案列表（使用中 / 未挂载）、guide 注入说明、降级策略 | §5 集成契约 |

- 半成品流水线（故障诊断本体 2/7、导入中 1/7）展示未配置阶段的占位状态，验证"创建时逐节点配置"的流程完整性。

### 3.4 知识库（对应修改思路 ⑤）

- **左栏**：知识库列表（名称 + 向量后端 + 状态徽标）；
- **右栏**：选中库的管理界面——文档列表（chunks 数、索引状态）、上传入口、**检索试运行**（输入检索词 → 展示命中段落与相似度分数；索引未就绪时按钮禁用）。

### 3.5 技能（对应修改思路 ⑥）

- **左栏（预留）**：可用的筛选器（全部 / 已挂载 / 未挂载，真实过滤右侧列表）+ 明确标注"规划中"的预留区（技能分组/标签、版本历史、市场导入）。
- **右栏**：技能列表卡片（名称 / 描述 / 工具数 / 挂载状态 / 编辑入口）+ 新建技能；编辑抽屉含指令内容（instruction，参考 Claude Skills 数据模型）与工具白名单，并注明安全边界（技能仅配置级注入，不提供脚本执行环境）。

## 5. 交互约定（全模块）

- 左列表选中态：高亮底色 + `aria-current`；折叠树使用原生 `details/summary`。
- 所有弹层使用 `dialog`（含遮罩、Esc 关闭）；反馈使用底部 toast。
- 演示按钮（新建 XX）点击后 toast 提示预期行为，不做真实创建。
- 支持 `prefers-reduced-motion`、键盘焦点样式与打印样式（打印时仅保留内容区）。

## 6. 待确认点

1. **对话与项目的从属关系**：目前演示为"项目下会话 ≙ Agent 对话的同一实例在项目视图打开"。若项目会话应为**独立实体**（不与 Agent 对话互通），需要调整数据模型与两个视图的关系展示。
2. **Agent 配置入口位置**：齿轮放在左栏 Agent 节点行内，是否需要在对话窗口配置条上也提供"编辑 Agent"快捷入口。
3. **本体流水线七阶段的颗粒度**：当前按 04 文档 S1~S7 全量视图化；若界面希望合并（如"构建"=S1~S4 一组），可折叠为一二级步骤。
4. **知识库 / 技能左栏预留区**的具体能力（分组、标签、市场）优先级。
5. **项目文件面板**：常驻右侧（当前）或改为按需弹出。
