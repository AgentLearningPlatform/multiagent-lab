## 1. 方案摘要

- **形态**：本地运行的 Web 多智能体平台。**两个 Go 进程**：
  - **主平台**（HTTP :8080）：Hertz API + 静态前端 + Agent/项目/对话/模型连接/知识库管理 + Eino ADK 运行时；
  - **本体服务 ontology-service**（HTTP :8090）：独立 SQLite + 本体 REST 管理 + **MCP Server**（本体查询工具）。
- **运行时**：Eino **ADK**。单 Agent 用 `ChatModelAgent`；多 Agent 默认 **AgentAsTool**（子 Agent 包成工具），对照实现 Transfer（`SetSubAgents`）；工作流用 Sequential/Parallel/Loop；全程 `Runner` + 事件流 → SSE。
- **模型**：页面内配置 OpenAI 兼容连接（默认预置 DeepSeek chat；embedding 另配），AES-256-GCM 加密存库；`ModelFactory` 按连接动态构造 `tool.BaseChatModel` / embedding。
- **知识库**：主平台内最简 RAG——固定长度切分 → embedding → SQLite 存向量 → 自研 `SQLiteRetriever`（实现 Eino Retriever 接口）→ 对话级注入。
- **本体（v0.4）**：独立服务；管理页走主平台**反向代理**调 REST；Agent 运行时经 **Eino MCP 工具（GetTools）**调用服务 `/mcp`；**编辑保存即按版本生效**（服务端写后失效缓存 + 读时版本校验）；服务不可用降级。
- **存储**：SQLite 单文件 ×2（主平台 / 本体服务），零外部依赖。
- **前端**：React 18 + TS + Vite + Zustand；SSE 流式 + 事件时间线；**本体管理两级页面：列表页 + 编辑页（JSON 形态 P0 / 图形化形态 P1：React Flow 画布 + RJSF 属性表单）**。

### 4.2 运行时流程（一次多 Agent 对话，v0.4 版）

1. 前端 POST `/api/conversations/{id}/messages`（携带启用知识库/本体开关状态）。
2. `ConversationManager` 装配：读对话 → 模型连接（解密 key）→ 项目配置（协作模式/成员 Agent）→ 知识库（文档/片段索引）→ **本体（v0.4：`OntologyClient` MCP `GetTools` 拉取 onto_* 工具 + REST guide 注入指引；失败降级）**。
3. `ModelFactory` 构造 ChatModel；按协作模式装配 ADK（AgentAsTool / SetSubAgents / Sequential…）。
4. `Runner.Run(ctx, userInput)` → 消费 `AgentEvent` 流 → 转发 SSE：`message.delta`、`tool.call`、`agent.switch`、`retrieval`（知识召回）、`ontology.query`（本体查询，含 version/via=mcp）、`error/done`；同时落库 Message + RunEvent。
5. 知识库启用时：先检索 TopK → 拼上下文 → 发 `retrieval` 事件；本体启用时：Agent 按需调用 onto_* MCP 工具。

### 4.4 启动顺序与降级（v0.4）

1. `ontology-service` 先起：监听 `127.0.0.1:8090`，自动迁移本体库，注册 `/mcp` 与 REST。
2. 主平台后起：启动时探测本体服务（`GET /healthz`），结果记入运行态 `ontologyReady`；**探测失败不阻塞主平台启动**，仅本体功能降级（REQ-19c/REQ-70）。

### 5.2 本体服务库（ontology-service SQLite，独立文件）

```sql
-- ontology-service/migrations/001_ontology.sql
CREATE TABLE ontology (
  id TEXT PRIMARY KEY,                    -- 如 onto_k8s_ops
  name TEXT NOT NULL,
  description TEXT DEFAULT '',
  spec_json TEXT NOT NULL,                -- {concepts[], relations[], instances[]}
  version INTEGER NOT NULL DEFAULT 1,     -- 每次 PUT 成功 +1（编辑即时生效锚点）
  created_at DATETIME, updated_at DATETIME
);
```

**设计说明：**

- **主平台 10 表 / 本体库 1 表**：知识三表与本体分属两库，天然演示"单体内 RAG vs 服务化本体"的对照。
- **连接类型与默认**：`model_connection` 带 `type`（chat/embedding），`is_default` 按 type 分别唯一；Agent 配 `model_conn_id` 空则用默认 chat 连接，知识库 `embedding_conn_id` 空则用默认 embedding 连接。
- **向量存储/状态机/维度**：chunk.embedding 存 `[]float32` JSON；`knowledge_doc.status`：`pending → embedding → ready|failed`（失败原因落 error）；`knowledge_base.embedding_dim` 首次向量化解。
- **跨库本体引用**：`conversation.ontology_id` 为字符串外部标识（本体服务生成如 `onto_k8s_ops`），不加外键；开关+选择随对话行持久化（REQ-19b）。
- **本体不拆实体表 + 缓存**：本体量小、整体读写，`spec_json` 整存整取 + `version` 版本号；服务内存持有解析后的图缓存，**写后失效 + 读时按版本校验**（见 §6.10 (5)）。
- **导入/导出（v0.5）**：外部格式解析在服务内 `internal/importer` 按格式独立实现（spec 直读、CSV nodes+edges 两表、GraphML XML；OWL/RDF 有损 P2），统一产出 `Spec` → 走与 PUT 相同的校验后入库（version=1）；导出为反向序列化下载。主平台仅透传代理，解析与校验都在本体服务。
- **不做配置快照**：Q-6 不追溯，运行时按"当前配置"装配，历史只存引用。

#### (4) REST API 与缓存一致性

```go
// internal/graphcache.go —— 写后失效 + 读时版本校验（编辑即时生效的核心）
func (c *Cache) GetGraph(ctx context.Context, id string) (*Graph, int64, error) {
    ver, _ := c.store.PeekVersion(ctx, id)      // ① 每次先看库中版本
    if g, ok := c.peek(id); ok && g.version == ver {
        return g, ver, nil                      // ② 命中且版本一致
    }
    spec, _ := c.store.LoadSpec(ctx, id)        // ③ 未命中/过期 → 重载
    g, _ := graph.Build(spec)
    c.put(id, g, ver)
    return g, ver, nil
}
// 写路径：PUT/导入成功 → version+1 → Invalidate(id)（下次读必重载）
```

> 结论：主平台**不缓存本体内容**，管理页每次保存版本 +1，Agent 侧下一次工具调用即新版本（REQ-70/REQ-73）。

#### (5) 校验（REQ-63）

`jsonschema` 校验结构 + `graph.Build` 校验引用（关系端点/实例类型必须指向已定义概念）；非法则 400 并返回错误列表。

**importer 解析规则（v0.5，Q-15 分层）：**

| format | 输入约定 | 映射 |
| --- | --- | --- |
| `spec` | 本服务导出的 spec_json | 直读（无损），补 name 校验 |
| `csv` | 两个文件/两段文本：`nodes.csv`（id,name,type,description,attrs_json）+ `edges.csv`(source,target,relation) | nodes 中 type∈已定义概念或以 nodes 内出现的新类型自动建 Concept；edges→Instance.Relations；attrs_json→Attributes |
| `graphml` | GraphML XML（Gephi/yEd 兼容） | node→Instance（`label`→name、`type` 键→Concept，无 type 归入 `Thing`）、edge→关系（edge 键 `relation`，缺省 `relatedTo`） |
| `owl/rdf/turtle` | Protégé 等导出 | **P2 有损**：`rdfs:label`→name、`rdfs:subClassOf`→关系、`owl:NamedIndividual`→实例；公理/推理语义丢弃，全部计入 warnings（REQ-69） |

导入统一流程（REQ-72）：解析 → 映射统计（concept/relation/instance 数量）+ warnings（无法识别条目）→ **校验**（与 PUT 同一校验器）→ version=1 入库 → 列表/对话下拉立即可见。

### 8.3 MCP 契约（本体服务 `/mcp`，Streamable HTTP）

- 传输：POST + SSE 响应（mark3labs `StreamableHTTPServer`，兼容 SSE 客户端）；客户端地址 `ONTOLOGY_MCP_URL`。
- 能力：仅 `tools/list` + `tools/call`；`tools/list` 返回**固定 4 个 onto_\* 工具**（不随本体内容变化，主平台初始化拉取一次即可）；无写工具（管理写操作只走 REST）。
- 入参约定：所有工具必带 `ontology_id`，服务端按其定位本体并按当前 version 查询（§6.10 (4)）。
- 降级：连接失败/超时 → 主平台不挂 onto_\* 工具并发 `ONTOLOGY_SERVICE_UNAVAILABLE`（§6.11）。

        if err == nil { ontoTools = g } else { emit(ONTOLOGY_SERVICE_UNAVAILABLE) }
        guide := onto.RESTGuide(convCfg.OntologyID)  // 失败容忍：跳过注入
        instruction += fmt.Sprintf(ontoGuideTmpl, convCfg.OntologyID, guide)
    }
    kbRetriever := buildRetrieverIfEnabled(convCfg)  // 知识库（v0.3）

    switch mode { case AgentAsTool: ... case Transfer: SetSubAgents... case Sequential/Parallel/Loop: ... }
    runner := adk.NewRunner(...)
    return &RunnerBundle{runner, ver, ontoReady: len(ontoTools) > 0}
}

func RunMessage(ctx, conv, userText) {
    bundle := Build(ctx, conv)
    input := injectKnowledge(userText, bundle.retriever) // 命中发 retrieval 事件
    for ev := range bundle.runner.Query(ctx, conv.ID, input) {
        classifyAndEmit(ev)   // onto_* → ontology.query{ontology_id, version, via:mcp}
        persist(ev)           // message/run_event
    }
}

## 13. 风险与对策

| 风险 | 触发 | 影响 | 对策 |
| --- | --- | --- | --- |
| Eino ADK API 变动 | 版本升级 | 编译失败 | 锁定 go.mod 版本；封装 `runtime/` 隔离 ADK 调用面 |
| AgentAsTool 上下文膨胀 | 子 Agent 多 | token 超限 | 限制项目成员数；子 Agent 输出要求摘要化 |
| Transfer 死循环 | 互相委派 | 请求悬挂 | MaxIterations + 委派深度计数 |
| SSE 断连 | 网络/代理 | 前端丢事件 | fetch 重连 + run_event 兜底重放 |
| 模型/向量连接不可用 | key 失效/额度 | 对话/向量化失败 | 连接测试前置 + 明确错误透传（REQ-16/59） |
| Key 泄露 | DB/仓库泄露 | 资损 | AES-256-GCM + master.key 分离 + 掩码回显 + .gitignore（REQ-44） |
| 本体 JSON 质量差/查不到 | 手工编辑出错 | 工具空、模型臆造 | 保存前 schema 引用校验；K8s 示例；"查不到"返回提示非报错；指引要求多跳不臆造 |
| **外部格式导入有损/歧义（v0.5）** | OWL 公理丰富、GraphML 属性命名随意、CSV 列不规范 | 导入后本体语义缺失/结构怪异 | 格式分层明确承诺（spec/CSV 基本无损、OWL 有损）；导入预览确认（REQ-72）；无法映射条目进 warnings 报告；解析器按格式独立实现（`internal/importer`）便于扩展与单独测试 |
| MCP 连接不稳 | 服务重启/超时 | 本体功能波动 | 指数退避重连 + 降级事件；`tools/list` 稳定不随本体内容变化 |
| 双进程缓存不一致 | 直改数据库 | 查到旧版本 | 强约束"只经 REST 写"；读时版本校验兜底 |
| 本体服务资源占用 | 实例量大 | 内存增长 | 学习尺度（千级实例内）全内存可接受；预留分页/懒加载 |
