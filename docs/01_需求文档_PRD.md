## 1. 项目背景与目标

### 1.1 一句话定位

用 **Go + CloudWeGo Eino（ADK）** 亲手做一个"迷你版 Coze"的多智能体协作平台，通过**从单 Agent 到多 Agent、从控制台到 Web、从纯对话到知识/本体增强**的渐进式开发，系统掌握多智能体应用的工程化开发。

### 1.2 为什么做（学习目标，优先级高于功能堆砌）

| 编号 | 学习目标 | 对应功能落点 |
| --- | --- | --- |
| LG-1 | 理解 Eino Component 抽象（ChatModel / Tool / Prompt）与一次模型调用 | 最简对话 |
| LG-2 | 掌握 ChatModelAgent 的 ReAct 循环、Runner、事件流（AgentEvent） | Agent 对话、工具调用过程展示 |
| LG-3 | 掌握会话记忆与持久化（Memory / Session / 历史回放） | 多轮对话、对话历史保存与重开 |
| LG-4 | 掌握自定义 Tool 的开发与挂载 | Agent 配置工具、工具调用可视化 |
| LG-5 | 理解 Middleware / Callback 横切能力 | 耗时日志、token 统计、统一约束、Trace |
| LG-6 | **掌握多智能体协作**：AgentAsTool（推荐）与 Transfer（SetSubAgents）两种模式 | 项目配置多 Agent、路由/委派 |
| LG-7 | 理解确定性编排：Sequential / Parallel / Loop Agent | 项目工作流模式（P1） |
| LG-8 | 掌握人机协同 Interrupt / Resume + Checkpoint | 危险操作审批（P2） |
| LG-9 | 掌握流式输出到前端的完整链路（SSE + 事件协议） | 右侧对话详情的打字机/事件渲染 |
| LG-10 | 具备"配置驱动地动态装配 Agent 运行时"的工程能力 | 创建 Agent、项目配置 Agent、模型连接配置后实时生效 |
| LG-11 | **掌握 RAG 最小闭环**：文档加载/切分/Embedding/检索/上下文注入 | 知识库模块（v0.3，P1） |
| LG-12 | **掌握结构化知识（本体）的组织与按需查询**：本体建模、JSON Schema、工具化检索 | 本体管理模块（v0.3，P1） |
| LG-13（v0.4） | **掌握 MCP（Model Context Protocol）服务化与跨进程工具调用**：MCP Server 暴露本体能力、Eino 作为 MCP Client 接入、REST/MCP 双协议、跨进程缓存一致性 | 独立本体服务（P1） |

> **取舍原则**：功能为学习服务。每个功能都应能对应至少一个学习目标；不为了"像 Coze"而引入与学习目标无关的复杂度（如计费、多租户、插件市场）。

### 1.3 与真实 Coze 的边界（明确不做什么）

本项目是**学习项目**，刻意裁剪以下企业级能力，避免陷入业务细节：

- **不做**用户注册登录、账户/多租户、权限体系、组织架构（Q-5 已确认：单用户本地运行，聚焦核心功能）。
- **不做**插件市场、付费、审核发布流程、模板商店。
- **不做**可视化拖拽画布（Q-7 已确认：多 Agent 关系用**表单配置 + JSON**表达，把精力放在运行时而非画布工程；注意：v0.5 的本体图形化编辑 REQ-71 是"本体编辑形态增强"，不与之冲突）。
- 知识库做**最简化 RAG**（REQ-50~59）：**不做** PDF/Word/Excel 等复杂格式解析、OCR、表格抽取，**不做**混合检索/Rerank/多路召回，**不做**外部向量数据库（Redis/Milvus 等）；仅支持纯文本/Markdown 的简单切分 + SQLite 存向量 + 自研余弦 TopK 检索。
- 本体做**最简化管理 + 独立服务**（REQ-60~73）：**不做** OWL/RDF 推理机、自动推理分类、SPARQL、图数据库；支持自定义 JSON 本体（概念/关系/实例）的**两级管理（列表页 + 编辑页）**、**外部格式导入**（v0.5 起 P1，按格式分层，OWL/RDF 为有损导入）与基于关键词/标识的精确查询。**本体服务本身保持最简**：不做本体服务的多租户、鉴权、集群、远程部署（v0.4）。
- **不做**高并发、分布式、多副本等生产级非功能目标（见 §7）。

## 2. 目标用户与典型场景

**唯一用户：开发者本人（本地学习使用）。**

| 场景编号 | 场景 | 描述 |
| --- | --- | --- |
| SC-1 | 直接对话单个 Agent | 在「Agent 模块」创建/选择一个 Agent，不进入项目，直接对它提问，验证某个 Prompt、工具或 Agent 行为 |
| SC-2 | 创建项目并组建 Agent 团队 | 新建一个项目（如"K8s 运维助手"），为项目挑选/配置多个 Agent（如分诊员、日志专家、变更专员），设定它们的协作方式 |
| SC-3 | 在项目对话中沟通项目事项 | 在某项目下新建多个对话（每个对话=一个具体议题/任务），在对话里与该项目配置好的 Agent 团队沟通，观察多 Agent 路由与协作过程 |
| SC-4 | 回看与复盘 | 重开历史对话，查看消息、工具调用、Agent 切换轨迹，用于理解 Agent 运行时行为 |
| SC-5 | 配置模型连接 | 在「设置」中维护一个或多个 OpenAI 兼容模型连接（默认预置 DeepSeek 对话连接），填入 key、测试连通、设为默认，供各 Agent 选用；另需配置一个"向量连接"供知识库使用 |
| SC-6 | 建知识库并在对话中引用（v0.3） | 新建知识库（如"K8s 故障手册"），粘贴/上传若干 Markdown/文本片段，系统切分向量化；在某对话输入区选择该知识库，提问时 Agent 基于召回片段作答，并能看到召回了哪些片段 |
| SC-7 | 建本体并在对话中启用（v0.3；v0.4 服务化；v0.5 两级管理+导入） | 在「本体管理」**列表页**新建或**导入外部本体文件**（直接成为新本体），**打开进入编辑页**维护本体内容（如 K8s 运维本体：概念 Pod/Node、关系 belongsTo、实例等）；**保存后对话侧立即可选可用**；在对话输入区打开"使用本体"开关并选择该本体，主平台经 **MCP 调用本体服务**，Agent 回答时可按需查询概念、关系与实例 |

## 3. 信息架构与页面需求

整体为**左右分栏 + 顶栏设置**布局（对标简化版 Coze/ChatGPT 工作台）。

```
┌──────────────────────────────────────────────────────────────────┐
│  顶栏：项目名 / 当前默认模型 / 新建入口 /  ⚙ 设置(模型连接)            │
├──────────────┬───────────────────────────────────────────────────┤
│  左侧边栏      │  右侧：对话详情区                                    │
│  · Agent 模块  │  ┌─────────────────────────────────────────────┐  │
│  · 项目模块    │  │对话标题 + 当前生效 Agent/协作模式/模型          │  │
│  · 对话管理    │  ├─────────────────────────────────────────────┤  │
│  · 知识库      │  │消息流（用户/Agent/工具/子Agent/知识召回事件）   │  │
│  · 本体管理    │  │                                             │  │
│  （可折叠分组） │  ├─────────────────────────────────────────────┤  │
│               │  │ 输入框（发送/停止）                            │  │
│               │  │ 工具条：知识库 ▾(可选/无)  ☑使用本体 本体▾(可选)│  │
│               │  └─────────────────────────────────────────────┘  │
└──────────────┴───────────────────────────────────────────────────┘
        本体管理页(REST) 与 对话中本体查询(MCP) 都由「本体服务」提供
```

### 3.1 左侧边栏

| 编号 | 模块 | 需求 | 优先级 |
| --- | --- | --- | --- |
| REQ-01 | Agent 模块 | 列出所有已创建的 Agent；支持「新建 Agent」「编辑」「删除（需二次确认）」 | P0 |
| REQ-02 | Agent 模块 | 点击某个 Agent 可直接进入与其的临时对话（SC-1） | P0 |
| REQ-03 | 项目模块 | 列出所有项目；支持「新建项目」「编辑」「删除」；项目可展开显示其下对话 | P0 |
| REQ-04 | 项目模块 | 项目详情/设置中可**配置该项目使用的一个或多个 Agent 及协作模式** | P0 |
| REQ-05 | 对话管理 | 在某项目下可「新建对话」；对话归属于项目；支持重命名、删除 | P0 |
| REQ-06 | 对话管理 | 左侧按"项目 → 对话"两级组织；提供"全部 Agent 直聊"的临时会话入口 | P1 |
| REQ-07 | 知识库模块（v0.3） | 左侧列出所有知识库；支持「新建知识库」「重命名」「删除」；点击进入知识库详情（文档/片段管理） | P1 |
| REQ-08 | 本体模块（v0.3；v0.5 两级管理，数据在本体服务） | 本体管理为**类知识库的两级形态**：①本体列表页——查询/搜索全部本体，支持「新建」「导入（外部文件成为新本体）」「导出」「重命名」「删除（二次确认）」（数据来自本体服务 REST）；②点击打开**本体编辑页**（JSON 编辑/只读预览，P1 增加图形化编辑形态）。**在编辑页打开/保存过的本体，即为对话输入区下拉中的可选项** | P1 |

> 说明：Agent 直聊（SC-1）是**不挂项目的临时/独立会话**，与项目对话在数据上区分（见 §5 中 `conversation.scope`）。知识库是主平台内的全局资源；**本体是独立本体服务管理的全局资源**，二者都不归属某个项目，在任意对话（含 Agent 直聊）中均可选择引用。

### 3.6 知识库模块（v0.3 新增，最简化 RAG；仍在主平台内）

| 编号 | 需求 | 优先级 |

### 3.7 本体管理模块（v0.3 新增；v0.4 改为**独立本体服务**提供；v0.5 两级管理 + 导入转正）

**部署形态（v0.4 关键变化）**：本体能力由一个**单独运行的本体服务**提供，本体数据存在本体服务自己的 SQLite 中（不与主平台共库）。它同时提供两类接口：

- **REST（给人/前端）**：本体的增删改查、校验、预览、**导入/导出（v0.5）**、示例加载——本体管理页调用；
- **MCP（给模型/Agent）**：把本体查询能力暴露为 MCP 工具——主平台 Agent 运行时作为 **MCP Client** 经 Eino `eino-ext/components/tool/mcp` 接入。

**管理形态（v0.5）**：与知识库一致的两级结构——**本体列表页**（管理多个本体：查询/新建/导入/导出/删除）→ **本体编辑页**（编辑单个本体内容）。编辑页打开/保存的本体即时成为对话输入区下拉的可选项（REQ-73）。

| REQ-73（v0.5） | **打开即用一致性**：本体编辑页保存或导入产生的新版本，对话输入区下拉与运行时查询**即时可见**（复用 REQ-70 的版本化生效机制，无需重启/刷新服务） | P1 |

> **为什么是独立服务（Q-13 决策背景）**：本体需要在专门的本体管理中**独立维护、可持续演化**，并希望同一份本体将来能被 Claude Desktop、Cursor、其他语言服务或其他 Agent 直接复用。独立服务 + MCP 让"本体的维护/存储/查询"与"Agent 应用"解耦、独立演进；代价是多一个进程与跨进程缓存一致性（见技术方案 §6.10、§13）。

> 本体与知识库的差异（写进 README 的学习结论）：知识库回答"资料里大概怎么说"（向量相似度，模糊、非结构化）；本体回答"实体之间确定的关系是什么"（结构化、可精确查询、无歧义）。两者可在同一对话同时开启、互补。**部署上知识库在主进程内、本体为独立 MCP 服务**，也正好形成"进程内能力 vs 服务化 MCP 能力"的对照（LG-11 vs LG-13）。

本体 JSON 最小结构（业务视角，字段定义详见技术方案 §5）：

```json
{
  "concepts": [{ "id": "Pod", "name": "Pod", "description": "最小部署单元" }],
  "relations": [{ "id": "belongsTo", "from": "Pod", "to": "Node", "name": "运行于" }],
  "instances": [{
    "id": "pod-order-1", "name": "order-1", "type": "Pod",
    "attributes": { "namespace": "prod", "phase": "Running" },
    "relations": [{ "relation": "belongsTo", "target": "node-7" }]
  }]
}
```

## 5. 核心数据概念（业务视角，非建表语句）

> 完整字段与建表见技术方案 §5。此处帮助确认"概念关系"是否符合你的预期。**v0.4 起数据按服务拆分**：主平台库与本体服务库各自独立。

- **ModelConnection（模型连接，主平台库）**：一条可复用的 OpenAI 兼容端点配置。v0.3 起带**类型**：`chat`（对话，默认预置 DeepSeek）或 `embedding`（向量，供知识库；DeepSeek 不提供，需另配）。各类型可有一条默认连接；Key 加密存储。
- **Agent（智能体，主平台库）**：可复用的配置实体（名称/描述/提示词/引用的对话模型连接/采样参数/工具）。**被创建一次，可被多个项目引用，也可单独直聊。**
- **Project（项目，主平台库）**：一组 Agent + 一种协作模式 + 项目级约束的组合，是一个"智能体团队编排配置"。
- **KnowledgeBase / KnowledgeDoc / KnowledgeChunk（知识库三件套，主平台库，v0.3）**：文档集合（绑定一个向量连接）→ 一次粘贴/上传的文档 → 切分后的最小检索片段（含 embedding）。
- **Ontology（本体，v0.3；v0.4 起存于本体服务库）**：一份结构化 JSON（概念/关系/实例）+ 版本号。**由本体服务独占存储**，经 REST 供管理页编辑（v0.5 起含导入导出）、经 MCP 供 Agent 查询；主平台库不存本体内容，只在对话里记录所引用的 `ontology_id`（外部标识）。
- **Conversation（对话，主平台库）**：分两种作用域：
  - `agent`：与单个 Agent 的直聊会话（SC-1）；
  - `project`：在某项目下新建的对话（SC-3），运行时按项目配置动态装配 Agent 团队。
  - v0.3 起对话可**关联至多一个知识库**（主平台内 id，可空）、**关联至多一个本体 + 启用开关**（v0.4：保存本体服务的外部 `ontology_id`，可空），为对话级运行配置。
- **Message（消息，主平台库）**：一条对话记录，含角色、内容、产生它的 Agent 名称、序号。
- **RunEvent（运行事件，主平台库）**：工具调用、Agent 切换、子 Agent 委派、**知识召回（v0.3）**、**本体查询（v0.3；v0.4 来源为 MCP 调用）**、流式片段、错误等过程事件，用于右侧"过程可观测"和历史复盘。
- **Tool（工具注册表，主平台）**：系统内可用工具的元信息（名称/描述/入参 schema），供 Agent 配置勾选；v0.3 起本体查询工具不进静态勾选表；**v0.4 起它是本体服务经 MCP 动态下发的工具**（Eino MCP Client 拉取），运行时按所选 `ontology_id` 注入。

关系基数：一个 Project 引用 N 个 Agent（多对多）；一个 Agent 引用 1 条对话模型连接（或跟随默认）；一个知识库含 N 个文档、一个文档含 N 个片段；一个对话最多引用 1 个知识库、1 个本体（本体 id 指向本体服务）；一个 Project 下有 N 个 Conversation；一个 Conversation 下有 N 条 Message 与 N 条 RunEvent。

## 6. 验收标准（Definition of Done）

**P0 全部满足即视为 v1.0 学习闭环达成：**

1. 能在「设置」中预置/填写 DeepSeek 对话连接、**测试连通成功**并设为默认；能新增第二个 OpenAI 兼容连接；列表中 key 为掩码、不明文回显。
2. 能在 Web 页面创建一个 Agent，配置名称/描述/提示词并选择模型连接，保存后立即可用。
3. 能不进项目，直接和该 Agent 多轮对话，回复**流式**呈现，刷新/重开后历史仍在。
4. 能创建项目，配置 ≥2 个 Agent 并选择协作模式；能在项目下新建对话并沟通项目事项。
5. 多 Agent 对话中，界面能看到**主 Agent 是否委派/切换到了子 Agent**，以及工具调用过程。
6. 后端基于 Eino **ADK** 真实装配（不是写死的假路由），`agent_as_tool` 与 `transfer` 两种模式至少各能跑通一个示例。
7. Agent/项目/模型配置变更后，**下一次运行/新对话**按新配置运行（配置驱动装配，无需改代码重启）。
8. 模型或工具报错时，界面有明确错误提示，后台有日志。

**P1 达成（v1.1）**：自定义工具勾选、三种工作流模式、项目级约束中间件、子 Agent 事件透传、连接停用与引用保护；**并新增知识与本体两条验收：**

9. **知识库闭环（LG-11）**：能新建知识库、粘贴/上传一份 Markdown 文本并完成切分与向量化（在设置中配好一个向量连接的前提下）；在对话中选择该知识库提问，回答基于召回片段，界面能看到召回来源与片段（REQ-17）；"试运行检索"能返回 TopK 片段与得分；未配向量连接时有明确引导。
10. **本体闭环（LG-12 + LG-13，v0.4；v0.5 补两级管理与导入）**：能启动**独立本体服务**；在**本体列表页**新建、搜索、删除本体，**打开进入编辑页**（内置 K8s 示例可一键加载），非法 JSON 被拦截；**导出 spec_json 备份、并将一份外部本体文件（spec/CSV）导入为新本体，导入预览确认后立即可在对话选用（REQ-68/72）**；在对话中打开"使用本体"并选择本体后，主平台**经 MCP** 调用本体服务，Agent 能正确回答"某实例属于什么/与谁有何关系"类问题，且 MCP 查询过程在时间线可见（REQ-18）；**在本体管理页修改并保存某本体后，不必重启服务，后续查询即按新版本返回**（REQ-73）；停掉本体服务时，普通对话与知识库仍可用且界面有明确提示（REQ-70）。

**P2 达成（v1.2+）**：Interrupt/Resume 审批、Trace 视图、DeepAgents 对照、本体 OWL/RDF 有损导入与 GraphML 导出增强（REQ-69，spec/CSV 导入已在 P1 交付）、知识库进阶（Rerank/混合检索/外部向量库/PDF 解析）、本体 MCP 服务对 Claude/Cursor 等外部客户端的直连复用验证。
