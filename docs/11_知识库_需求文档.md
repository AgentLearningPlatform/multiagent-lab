## 1. 定位与学习目标

| 项 | 内容 |
| --- | --- |
| 模块定位 | 知识库是主平台内的**全局资源**（非外部服务）：库列表/库详情两栏视图，文档入库→切分→向量化→检索→对话注入的完整闭环。 |
| 学习目标 | **LG-11（承接 01）**：掌握 RAG 最小闭环——文档加载/切分/Embedding/检索/上下文注入；v0.6 起基于开源组件搭建而非自研。 |
| 实现基调 | 开源优先（Q-18 已定）：向量存储与检索优先使用开源组件；自研仅保留 SQLite fallback 作学习对照。选型结论与对比分析见 12《知识库_方案设计.md》§5。 |
| 边界 | 简单 RAG：不做 PDF/OCR/表格抽取、Rerank/混合检索、GraphRAG 等进阶能力（需求池见 §4）；对话侧如何选择与引用知识库见 01（REQ-19a/19b/17/56）。 |

## 2. 需求列表

> 编号沿用 01 原 REQ 编号（可追溯），新增需求用 KB- 前缀。P1 为主（除注明）。

| 编号 | 名称 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| REQ-07 | 知识库界面（v0.7 同屏详情） | 知识库视图：左栏库列表（名称/状态徽标），右栏为选中库详情（文档/片段管理），同屏切换；支持「新建知识库」「重命名」「删除」 | P1 |
| REQ-50 | 知识库 CRUD | 新建/编辑/删除知识库：名称、简介；知识库为全局资源，可在任意对话引用 | P1 |
| REQ-51 | 内容接入 | 向知识库添加内容：支持**粘贴文本**、上传 `.txt` / `.md` 文件（UTF-8）；以"文档"为单位记录来源名 | P1 |
| REQ-52 | 文档切分 | 按固定长度 + 重叠（默认 500 字/重叠 50 字，可配置）的简单切分器切成片段（Eino 组件或轻量开源实现） | P1 |
| REQ-53 | 向量化与存储（开源优先，01 Q-18 / 12 D-KB1~3） | 用 embedding 连接把片段转向量，存入**开源向量存储**（首选本地轻量方案 Qdrant 容器；优先复用 eino-ext 现成 indexer/retriever 适配，实现时核对可用组件）；自研 SQLite 存向量方案降级为**无外部依赖 fallback / 学习对照** | P1 |
| REQ-54 | 文档/片段管理 | 知识库详情列出文档（可删除，级联清理片段与向量）；展示片段数、向量维度、更新时间 | P1 |
| REQ-55 | 索引状态可见 | 向量化进行中/成功/失败（失败显示原因）；支持对失败文档重建索引 | P1 |
| REQ-56 | 对话引用（**对话侧，保留 01 §3.6**） | 由 01 REQ-19a 选择知识库；提问时检索 TopK 片段（K 可配置，默认 4）注入上下文；交互语义归 01，检索与注入设计见 12 §3 | P1 |
| REQ-57 | 检索质量与试运行 | 可配置 TopK、相似度阈值；知识库详情提供"试运行检索"框，直接看召回片段与得分 | P1 |
| REQ-58 | 召回来源（**对话侧，保留 01 §3.6**） | 召回片段带来源（文档名/片段序号），回答过程可展开查看（01 REQ-17）；来源数据契约见 12 §3.4 | P1 |
| REQ-59 | 空库引导（**对话侧，保留 01 §3.6**） | 无向量连接或索引为空时，选择/提问给出明确引导，不静默用空知识作答（01 REQ-19b 联动） | P1 |
| KB-1（v0.1 新增） | 开源选型确认 | 向量存储/检索采用开源方案：eino-ext 现成适配优先 + Qdrant（P1 首选），自研 SQLiteRetriever 保留为无外部依赖 fallback 与学习对照；选型依据与替代方案对比（含 WeKnora 0.8.0 / RAGFlow 等）见 12 §5 | P1 |
| KB-2（v0.1 新增） | 进阶能力需求池（暂不实现） | 以下能力进入需求池，不排期：PDF/Word 等富格式解析与 OCR、表格抽取、父子分块/自适应分块、BM25 混合检索 + RRF 融合、Rerank 重排、查询改写、FAQ 索引、知识图谱（GraphRAG）、多平台同步（飞书/Notion 等）——对标 WeKnora 0.8.0 / RAGFlow 0.27 已有能力（见 12 §5）；触发条件成熟时经评审升级 | 池 |
| KB-3（v0.1 新增） | 独立 RAG 服务集成（P2 备选路线） | 若未来需要进阶能力且不自研：可参照 OpenOntologies 双轨模式（01 REQ-100），将 WeKnora（MIT，含 MCP Server）或 RAGFlow 以**独立服务**接入主平台（Agent 挂载其 MCP 工具），与本文档 P1 组件级方案并行、数据不互通、可整体摘除；是否启动由主人拍板 | P2 |

## 5. 场景与验收

| 场景 | 验收标准（承接 01 验收第 2/6 条口径） |
| --- | --- |
| SC-6 建库并引用 | 新建知识库 → 导入文本 → 完成切分向量化（开源向量组件）；对话选择该知识库提问，回答引用召回片段与来源；检索试运行可见片段与得分 |
| 组件切换验收 | SQLite fallback 与 Qdrant 路径下，同一知识库的检索试运行结果一致（TopK/阈值相同口径）；Store 切换仅改配置 |
