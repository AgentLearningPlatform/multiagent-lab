## 1. 现状与问题

### 1.1 现状盘点（2026-09-22 复核）

- 本体模块为单页 `web/src/pages/OntologyPage.tsx`（约 2000 行），信息架构为 **S1~S7 纵向流水线**：S1 本体来源 → S2 编辑 → S3 校验 → S4 可视化 → S5 运行方式 → S6 对外暴露 → S7 对接智能体；左栏本体列表带 S1~S6 完成度圆点（StageDots）。
- 运行方案**以单个本体为中心**（per-本体 S5 段）；S6/S7 内嵌在构建流水线尾部。
- `web/src/api/client.ts` 已**完整覆盖两平面**：`/api/ontologies*`（构建，:8091 反代）、`/api/runtime-profiles*`（运行，:8090 反代），含 start/stop/reload/logs/versions/artifacts/ai-draft/export 等，可全部复用。
- `ChatWindow.tsx` 已按 `runtime_profile_id` 挂载（"本体增强"chip）；guide 注入路由已补（4ebb957）。
- 学习支撑件（REQ-92/93/94）已实现后端与入口（SPARQL 工作台/源码视图/翻译透视），入口藏在方案详情页。
- semantica 独立栏已上线（f0c7502：worker+反代+独立栏+消费链路轻量版），属导航栏独立模块，不在本方案范围。

### 1.2 与主人定位的三处错位（v0.3 重判）

| # | 现状 | 定位要求（主人拍板） | 判定 |
| --- | --- | --- | --- |
| P1 | 流水线 S1~S7 串成一条线，构建与运行混杂 | 过程（构建）/结果（资产）/运行（方式）三栏分立；现有页面降为「自定义构建」流程，**S1~S4 保留，S5~S7 移交本体资产与本体运行模块** | ❌ 信息架构错位 |
| P2 | 运行方案 per-本体绑定、单一列表 | 运行方案全局一等实体，且**按运行方式（引擎）分组为二级模块**（每种运行方式一个侧边栏项） | ❌ 组织方式错位 |
| P3 | 学习视角无一级入口（学习件 REQ-75/76/90/91 全在 P2、引导视图可隐藏） | 学习者打开平台即可见**学习中心**（默认页）：七阶段路径 + 任务卡 + 构建方式对照 + 运行方式对照 | ❌ 定位错位（v0.3 核心） |

> 结论：功能覆盖面已够（REQ-90~96 学习件已登记），问题在**信息架构把学习视角放逐到末位**。本次改造 = IA 重组 + 学习中心一级化，"重排为主、重写为辅"。

## 2. 改造目标与不动项

**目标 IA（一句话）**：本体导航项内部改为**左侧边栏四栏**——**学习中心**（默认页）/ **本体构建**（按构建路径分二级模块）/ **本体资产**（统一仓库管理）/ **本体运行**（按运行方式分二级模块）；顶部导航六模块结构与 semantica 独立栏不变。

**不动项（本次不改）**：
- 后端 API 契约与双反代（`/api/ontologies*`、`/api/runtime-profiles*`、`/api/ontology-llm/generate`）；
- `client.ts` 现有 API 封装（全部复用，仅增量）；
- 主平台顶部导航六模块结构；semantica 独立栏及其零侵入定位（D-O10）；
- antd 6 + 现有样式体系（`pages.css` 的 `onto-*` 类）；
- `ChatWindow` 的 `runtime_profile_id` 挂载与 `ontology.query / ontology.unavailable` 事件渲染。

## 5. 页面设计

### 5.1 学习中心（LearnPage，默认页，REQ-104）

- **七阶段学习路径主视图**：S1→S7 横向路径条（数据源 = REQ-74 七阶段模型），每阶段节点展开：方法论卡片入口（`seeds/learning/methodology/`，REQ-90）、任务卡列表（目标/步骤/验收问题/打卡，REQ-91）、工具入口跳转（跳构建/运行/资产栏对应功能，不重复造功能）。
- **构建方式对照区**：五张路径卡（自定义构建 / OntoChat / semantica / OntoExtend / Open Ontologies），每卡标注：适用场景、学习要点、当前状态徽标（可用 / 部分可用 / 引导先行）、示例本体关联（REQ-91 四示例映射四路径）。走完一条任务卡点亮一枚。
- **运行方式对照区**：引擎差异卡（Oxigraph 无推理 / Fuseki 带推理 / Open Ontologies 物化推理+39 工具），推理对照入口在此露出（REQ-94，随 O6 Fuseki 激活；P1 显示"随 Fuseki 交付"置灰）。
- **进度视图**：按阶段聚合任务完成度（REQ-91 ④），打卡状态存 checklist（`task:` key 空间，REQ-76 机制复用）。
- 内容资产（REQ-90/91）**提前至 P1 尾交付**（D-O11）：方法论卡片五模块 + 2 个示例本体建模说明先行，4 示例随 P2 补齐；学习中心界面骨架不依赖 REQ-75 配置页，先跑固定默认工具链。

### 5.2 本体构建（BuildPage，按路径分二级模块）

- **二级导航**：五条路径各一个菜单项；每项右侧状态徽标（可用/部分可用/引导先行）。
- **自定义构建（可用，现有页面主体）**：保留七阶段前 4 步——S1 本体来源（导入/AI 创建/内置示例/空白四入口）→ S2 编辑（JSON 编辑器，图形化 REQ-71 后续接入）→ S3 校验 → S4 可视化（ReactFlow）；**S5~S7 卡片移除**（运行看本体运行栏、facade/挂载看运行方案详情）。步骤间自动流转，完成后引导跳转本体资产栏查看产物、本体运行栏部署。
- **OntoChat 流程（部分可用，REQ-103 模式 A）**：对话式多轮 CQ 引导生成——第一步列能力问题 → 逐轮补全领域信息 → 生成 spec_json 草稿 → 校验循环回喂 → 预览入库；复用 `/api/ontology-llm/generate`（多轮上下文为 REQ-103 模式 A 增量，P2 前段交付；交付前该页显示"对话式引导排期中"+现有单轮 AI 创建引导跳转）。参考 OntoChat 论文三部曲（登记簿 T1）。
- **semantica 流程（入口卡）**：说明卡（semantica 定位/多源摄取能力/与主线边界）+「前往 semantica 独立栏」跳转按钮。**不把 semantica 能力重收进构建平面**（保持 D-O10 零侵入）。
- **OntoExtend 流程（引导先行）**：方法论引导卡（对话式扩展现有本体是什么、参考论文、与 fork/REQ-82 的关系）+ 手工路径指引（导入已有本体 → AI 创建扩展 → 校验）。工程化登记需求池（P2/P3 评估）。
- **Open Ontologies 流程（引导 + 回流）**：引导卡（oo 能力面/双轨定位）+「前往 Open Ontologies 工作台」跳转；产物回流指引（导出 TTL → 主线导入，REQ-78 双轨互通 P2 后自动化）。

### 5.3 本体资产（AssetsPage，统一管理）

- **资产列表**：名称、来源徽标（导入/AI/示例/空白/自定义构建）、形态徽标（original TTL/OWL、spec_json）、版本号、构建段完成度 dots（S1~S4）、被 N 套方案引用（只读）、更新时间。
- **操作**：新建（引导跳转构建栏对应路径）、编辑、浏览、删除（Popconfirm 保留"级联删除 Spec/产物；已启动的运行方案不受影响"——REQ-87）。
- **详情工作区 Tabs**：Spec 编辑（JSON + 保存）｜校验（错误表 + 运行校验）｜版本历史（列表 + 任一版 original 源码查看 = REQ-93）｜产物清单｜可视化（ReactFlow）｜导出 TTL（自建本体入 SPARQL 型方案前置）。
- 保存成功固定提示："已保存新版本；运行方案需在其页面显式重载后生效"（REQ-87）。
- **不出现**：任何引擎、端口、启停配置（正交红线）。

### 5.4 本体运行（RuntimePage，按运行方式分组）

- **二级导航** = 运行方式清单：Oxigraph（可用）｜Fuseki（O6 后点亮）｜Open Ontologies（引导页）｜Cayley（P2 置灰）。数据源 = `listRuntimeProfiles()` 按 engine 过滤，无新后端。
- **引擎分组页（Oxigraph/Fuseki 共用模板）**：
  - 方案卡片：名称、引擎徽标、已加载本体 chips（多值）、状态五态徽标、端口/端点、健康摘要、最近错误（Tooltip 全文）。
  - 行操作：启动 / 停止 / 重载（REQ-87 显式重载）/ 编辑配置 / 删除（二次确认）/ 查看详情。
  - 页顶全局条：**引擎可用性预检条**（last_error 关键词映射友好文案，如 `executable not found` → 安装/容器指引）；**降级条**（:8090 不可达整页只读）。
  - **新建/编辑向导（Steps 三步，REQ-85）**：①运行时类型（本分组内固定为该引擎，P1 仅 Oxigraph 可选、Fuseki disabled 至 O6）；②勾选本体集合（多选，含"需先导出 TTL"引导）；③细节参数（名称/端口/端点可写/推理开关——Fuseki 推理开关激活，Oxigraph 灰置）。配置变更需重启提示。
  - **方案详情 Drawer**：概览（状态时间线/端点/配置）｜日志｜facade 与工具｜查询与挂载（挂载指引全局口径 + SPARQL 工作台 REQ-92 + 翻译透视 REQ-94）｜推理对照入口（Fuseki 分组显示，随 O6）。
- **Open Ontologies 分组页**：引导页——oo 定位（独立托管双轨/能力面/与两平面边界）、oo-worker 工作台跳转、数据边界说明（oo 数据不进主线仓库，回流路径指引）。非 managed 引擎，无启停管理。
