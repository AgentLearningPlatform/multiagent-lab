## 1. 项目背景与目标

### 1.1 一句话定位

用 **Go + CloudWeGo Eino（ADK）** 亲手做一个"迷你版 Coze"的多智能体协作平台，通过**从单 Agent 到多 Agent、从进程内运行到沙箱化、从纯对话到知识/技能/本体增强**的渐进式开发，系统掌握多智能体应用的工程化开发。

### 1.2 为什么做（学习目标，优先级高于功能堆砌）

| 编号 | 学习目标 | 对应功能落点 |
| --- | --- | --- |
| LG-1 | 理解 Eino Component 抽象（ChatModel / Tool / Prompt）与一次模型调用 | 最简对话 |
| LG-2 | 掌握 ChatModelAgent 的 ReAct 循环、Runner、事件流（AgentEvent） | Agent 对话、工具调用过程展示 |
| LG-3 | 掌握会话记忆与持久化（Memory / Session / 历史回放） | 多轮对话、对话历史保存与重开 |
| LG-4 | 掌握自定义 Tool 的开发与挂载 | Agent 配置工具、工具调用可视化 |
| LG-5 | 理解 Middleware / Callback 横切能力 | 耗时日志、token 统计、统一约束、Trace |
| LG-6 | **掌握多智能体协作**：AgentAsTool（推荐）与 Transfer（SetSubAgents）两种模式 | 项目配置多 Agent、路由/委派 |
| LG-7 | 理解确定性编排：Sequential / Parallel / Loop Agent | 项目工作流模式（P1） |
| LG-8 | 掌握人机协同 Interrupt / Resume + Checkpoint | 危险操作审批（P2） |
| LG-9 | 掌握流式输出到前端的完整链路（SSE + 事件协议） | 右侧对话详情的打字机/事件渲染 |
| LG-10 | 具备"配置驱动地动态装配 Agent 运行时"的工程能力 | 创建 Agent、项目配置 Agent、模型连接配置后实时生效 |
| LG-11 | **掌握 RAG 最小闭环**：文档加载/切分/Embedding/检索/上下文注入——v0.6 起**基于开源组件搭建**而非自研 | 知识库模块（P1） |
| LG-12 | 掌握结构化知识（本体）的按需查询与工具化检索 | 本体对接（细节见本体文档） |
| LG-13（v0.4） | **掌握 MCP 服务化与跨进程工具调用**：MCP Server/Client、多协议、跨进程一致性 | 本体对接 MCP facade、Agent 级 MCP 配置 |
| LG-14（v0.6，归属本体文档） | LLM 结构化生成与校验循环（本体 AI 创建） | 经主平台模型代理支撑（REQ-98），详见本体文档 REQ-82 |
| LG-15（v0.6） | **Agent 沙箱化执行**：Docker 容器 / K8s Pod 后端、镜像构建、配置下发、生命周期与资源限制 | REQ-122 执行后端（P2） |
| LG-16（v0.6） | **技能化能力封装**：技能包模型、提示词注入、工具合并、动态装配 | 技能管理（REQ-120/121） |

> **取舍原则**：功能为学习服务。每个功能都应能对应至少一个学习目标；不为了"像 Coze"而引入与学习目标无关的复杂度（如计费、多租户、插件市场）。

### 1.3 与真实 Coze 的边界（明确不做什么）

本项目是**学习项目**，刻意裁剪以下企业级能力，避免陷入业务细节：

- **不做**用户注册登录、账户/多租户、权限体系、组织架构（Q-5：单用户本地运行，聚焦核心功能）。
- **不做**插件市场、付费、审核发布流程、模板商店。
- **不做**可视化拖拽画布（Q-7：多 Agent 关系用**表单配置 + JSON**表达）。
- **不做**计费、审计、合规等企业运营能力。
- 知识库做**简单 RAG（v0.6 开源优先）**：**不做** PDF/OCR/表格抽取、Rerank/混合检索等进阶能力（留需求池）；向量存储与检索**优先用开源组件**（eino-ext 现成适配 + 开源向量库），自研实现仅作对照 fallback。
- 本体模块：**构建/运行实现移交本体文档**（REQ-80~88）；本文档只保留**对接契约**（§3.8）——对话挂载运行方案、MCP 接入、降级、模型代理。
- Agent 沙箱：**不做**多机集群调度、镜像仓库管理、自动扩缩容（本地 Docker/K8s 单机即可）。
- **不做**高并发、分布式、多副本等生产级非功能目标（见 §7）。

## 2. 目标用户与典型场景

**唯一用户：开发者本人（本地学习使用）。**

## 5. 核心数据概念（业务视角，非建表语句）

> 完整字段与建表见技术方案 §5。**v0.6 数据按服务拆分**：主平台库（智能体/对话/知识库/技能/文件）+ 本体模块自有存储（构建平面仓库、运行方案库，见本体文档）。

- **ModelConnection（模型连接，主平台库）**：OpenAI 兼容端点配置，带类型 `chat` / `embedding`；各类型可有一条**全局默认**（P1）；Key 加密存储。
- **Skill（技能，主平台库，v0.6 新增）**：可复用能力包——名称、描述、指令段（注入系统提示词）、工具白名单（可选）、资源（可选）；全局资源，供 Agent 勾选（P2）。
- **Agent（智能体，主平台库）**：可复用配置实体（名称/描述/提示词/模型引用/采样参数/工具/技能/MCP servers/执行后端）；**被多个项目引用，也可单独直聊**；v0.6 起 Agent 名下可挂多个对话（左侧树）。
- **Project（项目，主平台库）**：一组 Agent + 协作模式 + 项目级约束 + **项目文件空间（P3）**的组合。
- **KnowledgeBase / KnowledgeDoc / KnowledgeChunk（知识库三件套，主平台库）**：文档集合（绑定向量连接）→ 文档 → 切分片段；向量存开源向量存储（Q-18），主平台记录索引引用与状态。
- **ProjectFile / ConversationArtifact（项目文件与对话产物，P3）**：项目空间文件元数据 + 对话运行产物归属记录（实际文件存本地项目目录）。
- **Ontology / RuntimeProfile（本体与运行方案）**：**存储与实现在本体模块**（构建平面仓库 + Runtime Manager，见本体文档 §3.1/§4.1）；主平台库**不存本体内容**，只在对话里记录所挂**运行方案的外部 id**（`runtime_profile_id`，O-6 口径）。
- **Conversation（对话，主平台库）**：两种作用域 `agent`（Agent 直聊，Agent 名下多对话）/ `project`（项目下对话）；可关联至多一个知识库（主平台 id）、一个**本体运行方案**（外部 `runtime_profile_id` + 启用开关）、（P2）技能选择随 Agent 配置走；配置随对话保存、不追溯（Q-6）。
- **Message / RunEvent（消息与运行事件，主平台库）**：多角色消息 + 过程事件（工具调用、Agent 切换、知识召回、本体查询、技能注入、产物文件 P3、错误）。
- **Tool（工具注册表，主平台）**：系统内可用工具元信息；**动态工具来源扩展（v0.6）**：①本体运行方案经 MCP facade 下发（onto_*）；②Agent 级配置的 MCP servers 下发（P2）；③技能白名单合并。

关系基数：一个 Project 引用 N 个 Agent（多对多）；一个 Agent 引用 0~1 条对话模型连接（或跟随全局默认）；一个 Agent 名下 N 个直聊对话；一个对话最多引用 1 个知识库、1 个运行方案；技能与 Agent 多对多（P2）。

## 6. 验收标准（Definition of Done）

**P0 满足即 v1.0 学习闭环达成：**

1. 能在「设置」预置/填写 DeepSeek 对话连接、**测试连通成功**；列表中 key 为掩码、不明文回显。
2. 平台按**顶部导航五模块 + 设置**组织（Agent/项目/本体/知识库/技能；以《17_产品_信息架构与界面设计》为基线（原型已移除）；OpenOntologies 不设独立导航——v0.21 REQ-111 修订，其工作台经本体模块构建/运行入口进入）；能创建 Agent（名称/描述/提示词/显式选择模型连接），保存后立即可用；**Agent 视图左栏折叠树可展开该 Agent 的多个对话**，重开历史对话完整还原。
3. 单 Agent 多轮对话**流式**呈现；停止生成可用。
4. 能创建项目、配置 ≥2 个 Agent 与协作模式；项目树下新建对话并沟通，界面能看到**主 Agent 委派/切换到子 Agent**与工具调用过程；`agent_as_tool` 与 `transfer` 至少各跑通一个示例（基于 Eino ADK 真实装配）。
5. 配置变更后**下一次运行/新对话**按新配置运行（配置驱动装配，无需改代码重启）。
6. Agent 默认以 **inprocess 后端**运行（执行后端抽象已就位，接口可插拔）。
7. 模型或工具报错时，界面有明确错误提示，后台有日志。
