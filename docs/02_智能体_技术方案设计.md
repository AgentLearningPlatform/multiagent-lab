## 1. 方案摘要

- **形态**：本地学习用多智能体平台。Go 后端（CloudWeGo Eino / ADK）+ React SPA 前端；数据 SQLite；模型走 OpenAI 兼容协议（预置 DeepSeek）。
- **进程拓扑（v0.6）**：
  - `backend`（:8080）：智能体平台主体（Agent CRUD、对话编排、SSE、模型连接、知识库、技能、项目文件、本体对接代理）。
  - 本体模块两平面（**独立维护，见本体文档**）：`runtime-manager`（:8090，运行方案编排 + 统一 MCP facade）与构建平面 `ontology-service`（:8091，本体仓库/导入/编辑/校验）。
  - `oo-worker`（:8092，v0.8 P2）：**OpenOntologies 独立集成**——Go 薄服务托管 open-ontologies 单二进制（CLI exec + serve MCP 转发 + 工作台 REST），与主线两平面解耦、双轨并行可整体摘除（§6.15）。
  - 可选增强进程：Qdrant 容器（开源向量库，P1 知识库）、Agent 沙箱容器（P1+，每 Agent 一个 agent-runtime 实例）。
- **关键决策**：多 Agent 协作首选 AgentAsTool；配置驱动动态装配；对话级知识库/本体开关；**执行后端/向量存储/本体运行时均为可插拔抽象**；MCP 用 Streamable HTTP；**开源优先**——Eino/eino-ext、mcp-go、Qdrant、React Flow 等现成方案直接用，自研仅保留学习价值部分（§2.3）。
- **关键决策（v0.24 补）**：**Agent 推理实现层可插拔**（§6.16，新增 D-O13）——与 §6.3 容器层（"在哪儿跑"：inprocess/docker/k8s）正交的"谁来推理"维度。自研 eino-adk 后端 P0 默认（完整 Eino ADK 能力）+ 外部本地 CLI 适配后端 P1（Claude Code / OpenCode / Aider，PATH 探测 + 协议桥接）；外部后端技能/MCP 降为 instruction 注入，AgentAsTool/工作流编排不暴露。
- **关键决策（v0.25 补）**：**知识库模块拆为双子模块**（§6.9 + 12 KB v0.2，新增 D-KB4）——「**向量检索 RAG**」「**GraphRAG 检索**」在同一模块页内**左侧边栏 tab 区分**（顶部 tab，KG 实体徽标「RAG / GraphRAG」），共享 chunk 池，由 `kb.mode` 字段区分（默认 'rag'）。GraphRAG 子模块**0 自研**，复用本体侧 semantica worker :8093（钉版本 v0.6.8+，已实现 ingest_ttl + GraphRAG query；扩展 `POST /graphrag/ingest` 接受任意 chunk 集合）；KG 实体/关系**只落 semantica 侧**，主平台不重存；语义检索端点 `POST /api/kbs/{id}/graphrag-search` 经 `/api/semantica/*` 反代；`retrieval` SSE 事件增 `mode` 字段。学习价值对齐：同一文档库的两种检索面（精确 chunk 检索 vs 语义图谱检索），与本体侧"facade 精确查询 vs semantica 语义问答"形成两层对照（基础 RAG 层 + 本体语义层）。
- **关键决策（v0.26 补）**：**本体构建栏第六路径「由知识库构建本体」**（§6.10 同步 + 12 KB v0.3 §3.5 + 03 v0.10 REQ-108 + 04 v0.13 §3.7，新增 D-O14，方案 A）——本体模块左侧边栏仍四栏（D-O11 IA 不变），构建路径从 5 扩为 6。**三种抽取策略**——A：KB chunk 池 → LLM 抽 spec_json（复用 REQ-82 `/api/ontology-llm/generate` + REQ-90 CQ 引导，可即时上线）；B：KB GraphRAG KG → 直转 spec_json（v0.13 semantica worker `/graphrag/ingest` 已扩展接受 chunk 集合，主平台薄映射层 <300 行 entity→Concept/relation→Relation/claim→Attribute，P2 后评估）；C：混合（KG 作初稿 + LLM 校验 + 补全，P2）。**新 REST 端点**：GET /api/kbs/selectable-for-ontology-build + POST /api/ontologies/build-from-kb + POST /api/semantica/chunks-to-kg + POST /api/ontologies/kg-to-spec-json。**闭环对偶**：本路径 KB→本体构建闭环与 §6.10 semantica 本体→KG 消费闭环形成「文本→三种语义资产形态」完整矩阵（RAG 片段 / KG / 本体），与本体侧四环节（构建/运行/消费/审计）形成「文本→不同形态资产」完整映射。**状态**：策略 A 部分可用（最早随 M6 KB 模块完成 + M14 KB 双子模块 + REQ-82 已就绪即可立项）；策略 B/C P2。**示例本体**：`seeds/learning/ontologies/` 增第 5 个「设备故障知识库 → 设备故障本体」（P2）。**前置**：D-KB4（v0.25 KB 双子模块）+ v0.13 semantica worker chunk 接受。
- **对接本体（v0.6 收编）**：主平台不实现本体，只做 MCP Client（连 Runtime Manager facade）+ 双反向代理 + 降级 + 模型能力代理；对话挂载**运行方案**（`runtime_profile_id`，本体文档 O-6 口径）。

### 2.2 In Scope / Non-Goals

```go
func (b *Assembler) BuildAgent(ctx context.Context, a *agent.Agent) (*adk.ChatModelAgent, error) {
    cm, err := b.models.ChatModelOrDefault(ctx, a.ModelConnID) // Agent 级覆盖 → 全局默认（P1）

    })
```

### 6.3 AgentRuntimeBackend（执行后端抽象，v0.6 新增 §6.12）

```go
type AgentRuntimeBackend interface {
    Start(ctx context.Context, agentID string) (Endpoint, error) // inprocess 返回内存句柄；沙箱返回 http endpoint
    Stop(ctx context.Context, agentID string) error
    Status(ctx context.Context, agentID string) (BackendStatus, error) // running|stopped|error + 资源信息
}
```

- **inprocess（P0 默认）**：`Start` = 进程内 `Assembler.BuildAgent` + Runner 缓存；`Endpoint` 为内存句柄，零部署成本，快速实现路径。
- **docker（P1）**：每 Agent 一个容器跑 **agent-runtime 镜像**（`backend/agentd`）：
  - 启动：`docker run --name agt-{agentID} --memory=512m --cpus=1 -e AGENT_ID=... -e PLATFORM_URL=http://host:8080 agentd:latest`；端口 `-P` 随机映射，`Start` 返回映射端点并登记注册表。
  - **配置下发**：agentd 启动时 `GET /api/internal/agents/{id}/manifest`（内部端点，带一次性 token）拉取完整配置（模型连接、技能、工具、MCP），在容器内完成 ADK 装配——**主平台与沙箱共用同一份装配代码**（`Assembler` 抽为共享包）。
  - 对话请求：主平台 `POST {endpoint}/run`（SSE 透传）；agentd 内事件协议与主平台 §7 一致。
  - 生命周期：主平台进程重启后按注册表对账（容器存在则复用，不存在重建）；资源限制由启动参数固定。
- **k8s（P2）**：每 Agent 一个 Pod（agent-runtime 镜像 + `requests/limits` + ConfigMap 注入 manifest）；client-go 起/删/查；主平台经 Service/Port-forward 访问。学习尺度：单集群。
- **一致性验收**：inprocess 与 docker 对同一 Agent 配置产出一致回答（PRD 验收 14）。

> Q-17 反转条件：无 Docker/K8s 环境 → 长期 inprocess；无隔离诉求 → docker 后端延后。接口先行保证切换零成本。

8. **入库异步抽 KG**（仅 GraphRAG 子模块）：chunk 写入 `chunk` 表后，后台 goroutine 把 chunk 集合 POST 给 semantica worker `:8093 POST /graphrag/ingest`（v0.2 接口扩展，KB-O4）；失败 → 重试 3 次 → 标记 doc 为「KG 抽取失败，检索降级到 RAG 模式」（降级不阻断主流程）。
9. **降级语义**：semantica worker 不可达 → `retrieval` 事件 mode='graphrag' 但 `degraded: true` 字段；UI 显示「GraphRAG 服务不可达，本次用 RAG 降级」轻提示；worker 恢复后下一条消息自动恢复（不持久化降级标记）。

### 6.16 Agent 推理后端可插拔（v0.24 新增，D-O13）

**定位**：与 §6.3/§6.12 容器层（"**在哪儿跑**"：inprocess / docker / k8s）**正交**的推理实现层（"**谁来推理**"）可插拔。容器层决定 Agent 进程跑在同进程 / Docker / K8s Pod；推理层决定 Agent 推理由哪套实现完成（自研 Eino ADK 或本地已装的外部 CLI 工具）。

**目标**：把"Agent 后端实现"做成可配置项——平台默认走自研 Eino ADK（能力最完整），用户也可选择让 Agent 推理由本地已装的 AI 编码工具 CLI 代理（Claude Code / OpenCode / Aider）。学习价值对齐 LG「可插拔推理后端」：避免重复造轮子，复用本地已有工具链。

#### 6.16.1 后端形态（P0 默认 + P1 增量）

- **eino-adk 自研后端（P0 默认，向后兼容）**：调用 §6.2 `Assembler.BuildAgent` 装配 + §6.3 inprocess `Runner` 跑 Eino ADK。**完整能力**：系统工具 / 技能 instruction 注入 / 工具白名单合并 / Agent 级 MCP 多 server / AgentAsTool / SetSubAgents / 工作流编排 / 记忆 / 中断恢复等全量。
- **外部 CLI 适配后端（P1 增量，三代表）**：
  - **claude-code 后端**（Anthropic 官方 CLI，事实标准）：通过 `claude --print --input-format stream-json --output-format stream-json --verbose --dangerously-skip-permissions` 启子进程 + JSON 协议桥接；模型由 Agent 配置覆盖（Claude Code 默认 Sonnet/Opus，可改用主平台模型连接的 model id 注入）。
  - **opencode 后端**（开源终端 AI 编码工具，Apache-2.0）：通过 `opencode serve` HTTP server（默认 `:4096`，`POST /session/{id}/message` SSE）桥接；model / provider 走 OpenCode 自有 config。
  - **aider 后端**（开源配对编程，Apache-2.0）：通过 `aider --model <m> --no-auto-commits --message-file <path>` 非交互模式 + stdout JSON 解析；模型覆盖以 `--model` 注入。

#### 6.16.2 接口契约

```go
type AgentInferenceBackend interface {
    Name() string                                    // "eino-adk" / "claude-code" / "opencode" / "aider"
```

#### 6.16.3 适配器注册与发现

- 启动时遍历已注册后端列表（`internal/inference/adapters/`），对每个外部后端调 `Probe`；结果缓存到内存（10 分钟 TTL）+ 落库（`inference_backend_probe` 表，最近一次探测状态）。

#### 6.16.6 风险

主要三类风险——外部 CLI 协议版本不稳（升级破坏 JSON schema）、模型锁定（CLI 默认用自己的模型）、进程泄漏（网络异常 / 关页面）。对策：适配器 pin 版本范围 + Probe 失败降级到自研；model 覆盖通过 CLI 参数注入主平台 model id；Cancel 调用杀进程组 + 启动 watchdog 清理残留。详见 §13 风险表三条对应条目。

> **v0.29 实现回写注记（M13/D-O13，commit 11e3973）**——与上文设计的偏差与取舍，以本注记为准：

## 11. 装配与运行伪代码（主链路，v0.6）

```go
// Runner：一次对话运行
func (r *Runner) Run(ctx context.Context, conv *Conversation, input string, emit Emit) error {
    cfg := r.loadConvConfig(ctx, conv)            // 知识库 / runtime_profile / agent 集合
    var promptCtx string
    if cfg.KB != nil {                            // 知识库（开源检索，§6.9）
        hits, _ := r.kb.Search(ctx, cfg.KB.ID, embed(input), cfg.KB.TopK, cfg.KB.MinScore)
        emit(Event{"retrieval", hits}); promptCtx = render(hits)
    }
    team := r.assemble(ctx, cfg, emit)            // 按 collab_mode 装配（§6.4），
                                                  //   内部：技能注入（§6.12）+ 工具三源合并（§6.8/6.11）
                                                  //   + 按执行后端分发（§6.3）：inprocess 装配 | 沙箱 /run 转发
    stream, err := team.Run(ctx, input, promptCtx)
    if err != nil { return wrapErr(err, emit) }   // 模型/工具/本体 facade 错误 → run.error
    for ev := range stream { translate(ev, emit) } // → §7 SSE
    persistMessagesAndEvents(ctx, conv, stream)
    return nil
}
```
