## 1. 方案摘要

- **形态**：本地学习用多智能体平台。Go 后端（CloudWeGo Eino / ADK）+ React SPA 前端；数据 SQLite；模型走 OpenAI 兼容协议（预置 DeepSeek）。
- **进程拓扑（v0.6）**：
  - `backend`（:8080）：智能体平台主体（Agent CRUD、对话编排、SSE、模型连接、知识库、技能、项目文件、本体对接代理）。
  - 本体模块两平面（**独立维护，见本体文档**）：`runtime-manager`（:8090，运行方案编排 + 统一 MCP facade）与构建平面 `ontology-service`（:8091，本体仓库/导入/编辑/校验）。
  - `oo-worker`（:8092，v0.8 P2）：**OpenOntologies 独立集成**——Go 薄服务托管 open-ontologies 单二进制（CLI exec + serve MCP 转发 + 工作台 REST），与主线两平面解耦、双轨并行可整体摘除（§6.15）。
  - 可选增强进程：Qdrant 容器（开源向量库，P1 知识库）、Agent 沙箱容器（P1+，每 Agent 一个 agent-runtime 实例）。
- **关键决策**：多 Agent 协作首选 AgentAsTool；配置驱动动态装配；对话级知识库/本体开关；**执行后端/向量存储/本体运行时均为可插拔抽象**；MCP 用 Streamable HTTP；**开源优先**——Eino/eino-ext、mcp-go、Qdrant、React Flow 等现成方案直接用，自研仅保留学习价值部分（§2.3）。
- **关键决策（v0.24 补）**：**Agent 推理实现层可插拔**（§6.16，新增 D-O13）——与 §6.3 容器层（"在哪儿跑"：inprocess/docker/k8s）正交的"谁来推理"维度。自研 eino-adk 后端 P0 默认（完整 Eino ADK 能力）+ 外部本地 CLI 适配后端 P1（Claude Code / OpenCode / Aider，PATH 探测 + 协议桥接）；外部后端技能/MCP 降为 instruction 注入，AgentAsTool/工作流编排不暴露。
- **关键决策（v0.25 补）**：**知识库模块拆为双子模块**（§6.9 + 12 KB v0.2，新增 D-KB4）——「**向量检索 RAG**」「**GraphRAG 检索**」在同一模块页内**左侧边栏 tab 区分**（顶部 tab，KG 实体徽标「RAG / GraphRAG」），共享 chunk 池，由 `kb.mode` 字段区分（默认 'rag'）。GraphRAG 子模块**0 自研**，复用本体侧 semantica worker :8093（钉版本 v0.6.8+，已实现 ingest_ttl + GraphRAG query；扩展 `POST /graphrag/ingest` 接受任意 chunk 集合）；KG 实体/关系**只落 semantica 侧**，主平台不重存；语义检索端点 `POST /api/kbs/{id}/graphrag-search` 经 `/api/semantica/*` 反代；`retrieval` SSE 事件增 `mode` 字段。学习价值对齐：同一文档库的两种检索面（精确 chunk 检索 vs 语义图谱检索），与本体侧"facade 精确查询 vs semantica 语义问答"形成两层对照（基础 RAG 层 + 本体语义层）。
- **关键决策（v0.26 补）**：**本体构建栏第六路径「由知识库构建本体」**（§6.10 同步 + 12 KB v0.3 §3.5 + 03 v0.10 REQ-108 + 04 v0.13 §3.7，新增 D-O14，方案 A）——本体模块左侧边栏仍四栏（D-O11 IA 不变），构建路径从 5 扩为 6。**三种抽取策略**——A：KB chunk 池 → LLM 抽 spec_json（复用 REQ-82 `/api/ontology-llm/generate` + REQ-90 CQ 引导，可即时上线）；B：KB GraphRAG KG → 直转 spec_json（v0.13 semantica worker `/graphrag/ingest` 已扩展接受 chunk 集合，主平台薄映射层 <300 行 entity→Concept/relation→Relation/claim→Attribute，P2 后评估）；C：混合（KG 作初稿 + LLM 校验 + 补全，P2）。**新 REST 端点**：GET /api/kbs/selectable-for-ontology-build + POST /api/ontologies/build-from-kb + POST /api/semantica/chunks-to-kg + POST /api/ontologies/kg-to-spec-json。**闭环对偶**：本路径 KB→本体构建闭环与 §6.10 semantica 本体→KG 消费闭环形成「文本→三种语义资产形态」完整矩阵（RAG 片段 / KG / 本体），与本体侧四环节（构建/运行/消费/审计）形成「文本→不同形态资产」完整映射。**状态**：策略 A 部分可用（最早随 M6 KB 模块完成 + M14 KB 双子模块 + REQ-82 已就绪即可立项）；策略 B/C P2。**示例本体**：`seeds/learning/ontologies/` 增第 5 个「设备故障知识库 → 设备故障本体」（P2）。**前置**：D-KB4（v0.25 KB 双子模块）+ v0.13 semantica worker chunk 接受。——**⚠️ v0.32 注（D-O15）**：worker 依赖已退役；策略 A/B/C 均已交付（c56ebd4 + D-O15 自存 KG 切换），POST /api/semantica/chunks-to-kg 退役（现行 API 面见 §6.9 v0.31）。
- **对接本体（v0.6 收编）**：主平台不实现本体，只做 MCP Client（连 Runtime Manager facade）+ 双反向代理 + 降级 + 模型能力代理；对话挂载**运行方案**（`runtime_profile_id`，本体文档 O-6 口径）。

### 2.2 In Scope / Non-Goals

- **In Scope（v0.7）**：智能体管理（含执行后端抽象与沙箱化）、对话与 Agent/项目视图折叠树（顶部导航五模块）、项目多 Agent 协作、模型连接（含全局默认）、知识库（开源 RAG）、技能管理（CRUD + 注入 + 挂载）、项目文件与对话产物（P3）、**本体对接**（MCP facade 接入/挂载运行方案/降级/双反代/模型代理）、SSE 事件协议、Key 加密。
- **Non-Goals**：登录/多租户/权限、计费审计、画布编排、插件市场、PDF/OCR/Rerank 等进阶 RAG、多机集群与镜像仓库管理（沙箱仅本地单机尺度）、本体构建/运行实现（移交本体文档）、生产级高可用。

## 3. Eino ADK 能力映射（模块 ↔ Eino 概念）

### 4.2 运行时流程（主对话，v0.6）

1. 前端 `POST /api/conversations/{id}/runs`（SSE）。
2. 主平台按会话归属（agent/project）取 Agent 配置（含执行后端、技能、MCP servers）→ **技能注入**（§6.13）→ **工具装配**（系统注册工具 + 技能白名单 + 本体 facade 工具 + Agent 级 MCP 工具，P2）。
3. **执行后端分发**（§6.12）：`inprocess` → 进程内 ADK 装配并 `Runner.QueryStream`；`docker/k8s` → 调沙箱实例 `/run`（SSE 转发，配置经启动时下发）。
4. 事件逐帧翻译为 §7 SSE 协议推送；终态写 message + run_event。
5. 知识库：若对话选了知识库 → 提问前先检索（开源组件或 fallback）→ 拼上下文 + `retrieval` 事件。
6. 本体：若挂载运行方案 → facade 工具入参带 `ontology_id`；方案不可用 → `ONTOLOGY_SERVICE_UNAVAILABLE`（带 profile_id）。

### 6.3 AgentRuntimeBackend（执行后端抽象，v0.6 新增 §6.12）

```go
type AgentRuntimeBackend interface {
    Start(ctx context.Context, agentID string) (Endpoint, error) // inprocess 返回内存句柄；沙箱返回 http endpoint
    Stop(ctx context.Context, agentID string) error
    Status(ctx context.Context, agentID string) (BackendStatus, error) // running|stopped|error + 资源信息
}
```

- **inprocess（P0 默认）**：`Start` = 进程内 `Assembler.BuildAgent` + Runner 缓存；`Endpoint` 为内存句柄，零部署成本，快速实现路径。
- **docker（P1）**：每 Agent 一个容器跑 **agent-runtime 镜像**（`backend/agentd`）：
  - 启动：`docker run --name agt-{agentID} --memory=512m --cpus=1 -e AGENT_ID=... -e PLATFORM_URL=http://host:8080 agentd:latest`；端口 `-P` 随机映射，`Start` 返回映射端点并登记注册表。
  - **配置下发**：agentd 启动时 `GET /api/internal/agents/{id}/manifest`（内部端点，带一次性 token）拉取完整配置（模型连接、技能、工具、MCP），在容器内完成 ADK 装配——**主平台与沙箱共用同一份装配代码**（`Assembler` 抽为共享包）。
  - 对话请求：主平台 `POST {endpoint}/run`（SSE 透传）；agentd 内事件协议与主平台 §7 一致。
  - 生命周期：主平台进程重启后按注册表对账（容器存在则复用，不存在重建）；资源限制由启动参数固定。
- **k8s（P2）**：每 Agent 一个 Pod（agent-runtime 镜像 + `requests/limits` + ConfigMap 注入 manifest）；client-go 起/删/查；主平台经 Service/Port-forward 访问。学习尺度：单集群。
- **一致性验收**：inprocess 与 docker 对同一 Agent 配置产出一致回答（PRD 验收 14）。

> Q-17 反转条件：无 Docker/K8s 环境 → 长期 inprocess；无隔离诉求 → docker 后端延后。接口先行保证切换零成本。

9. **降级语义**：semantica worker 不可达 → `retrieval` 事件 mode='graphrag' 但 `degraded: true` 字段；UI 显示「GraphRAG 服务不可达，本次用 RAG 降级」轻提示；worker 恢复后下一条消息自动恢复（不持久化降级标记）。
10. **KG 源自研（v0.31 追加，D-O15/REQ-110）**：v0.25~v0.27 的 2/6/8/9 条中「semantica worker / `/api/semantica/*` 反代」口径全部作废——graphrag 模式导入即自动建自存 KG（LLM 抽取失败规则回退，再失败 degraded 不阻断）；graphrag-search 走三步检索（向量命中→KG 一跳扩展，KG 空/无命中回退纯向量标 degraded）；决策/溯源审计走 `/api/audit/*` + PROV-O 导出（本体第五栏「消费与审计」承载）。

### 6.13 Agent 对外 MCP 服务化（REQ-131，v0.47 立项——✅ 已排期 M18）

**定位**：agent-as-MCP-server——平台对外暴露统一 MCP Server 端点，把开启「对外服务」的 Agent 作为 MCP 工具供外部服务/Agent 调用；与 §6.11（Agent 作为 MCP client 调用外部 MCP）构成**双向闭环**，补齐 LG-13 的 server 侧（此前方案仅含 client 侧）。

**端点与协议**：主平台 Hertz 挂载 `/mcp`（**Streamable HTTP**，与 Q-14 传输口径一致）；实现复用 `mark3labs/mcp-go` 的 server 包（v0.43.0 已在依赖中，与 client 同一 SDK，零新增依赖）。默认仅回环监听（127.0.0.1），需要跨机访问时经部署视图反代按需暴露。

**工具映射**：每个开启对外服务的 Agent → 一个 MCP 工具：
- 工具名 `agent_{id}`（Agent 可配 tool_name 覆盖）；description 取 agent.description + 标准调用说明；
- 入参 schema：`{ input: string, session_id?: string }`；
- **工具式（先行）**：无状态——每次调用发起一次独立 run，最终回复作为工具响应返回；
- **会话式（增强，P2 后段）**：session_id 映射平台会话（scope=agent 直聊树），同一 session_id 多轮延续上下文。

**复用面（零新运行时路径）**：MCP server 工具处理器 → `Assembler.Build`（模型/工具/技能/MCP servers/知识库/本体挂载全自动生效，与对话窗口一致）→ `chat.Service.Run(...)`（emit 事件照常写入 run_events）→ RunResult 最终回复作为 MCP 工具响应返回。外部调用产生的会话归属 scope=agent，标题前缀 `[MCP调用]` 便于识别；REQ-117 装配快照增补 serve 配置段。

**安全边界**：

| 项 | 口径 |
| --- | --- |
| 鉴权 | Agent 级静态 Token（Bearer），开启时自动生成、可重置；Token 缺失/错误拒答 |
| 审批 | tool_approval≠off 的 Agent：server 会话内需审批工具**默认拒绝**并返回说明文本（server 模式无 UI 交互面）；异步审批回调（批准后继续）入需求池 |
| 防循环 | ①装配校验拒绝将本平台 `/mcp` 端点配置进任一 Agent 的 mcp_servers（自引用）；②跨调用深度上限（调用链事件头 depth，超过 N 层拒绝），防 agent→server→agent→… 链式递归膨胀 |
| 观测 | 被调用过程事件照常入库，对话窗口可回放（REQ-117 事件流重放）；运行来源标注 external:mcp |

**数据库与 API**：agent 表规划加列 `mcp_serve TEXT DEFAULT '{}'`（`{enabled, token, tool_name}`，迁移编号顺延，见 §5.1）；Agent CRUD 透传该字段；`GET /api/agents/{id}/mcp-serve` 返回端点地址/工具名/调用示例（Token 掩码）。SSE 与对话 API 不变。

#### 6.16.6 风险

主要三类风险——外部 CLI 协议版本不稳（升级破坏 JSON schema）、模型锁定（CLI 默认用自己的模型）、进程泄漏（网络异常 / 关页面）。对策：适配器 pin 版本范围 + Probe 失败降级到自研；model 覆盖通过 CLI 参数注入主平台 model id；Cancel 调用杀进程组 + 启动 watchdog 清理残留。详见 §13 风险表三条对应条目。

> **v0.29 实现回写注记（M13/D-O13，commit 11e3973）**——与上文设计的偏差与取舍，以本注记为准：
> ①适配器落地为单包 `internal/inference`（`inference.go` 接口/注册表 + `adapters.go` 全部适配器），未按 `adapters/` 目录拆分（体量小，拆分无收益）；探测结果**仅内存缓存 10min TTL**，`inference_backend_probe` 落库表延后（重启后首次访问重探测，代价可忽略）。
> ②**协议实现取舍**：claude-code 取 `claude -p <prompt> --output-format stream-json --verbose`（提示词走 argv，免 stdin 协议对接；JSONL 事件转译 message.delta / tool.call，result 行兜底）；opencode 取 `opencode run <prompt>` 非交互子命令（方案原文 serve HTTP + SSE——免会话生命周期管理，降级语义等价）；aider 取 `--message <prompt> --no-auto-commits --no-git --yes-always`（--no-git 免仓库假设），纯文本行级过滤 UI 噪声转译。

> ④**进程生命周期**：`exec.CommandContext` + `WaitDelay=3s`——Cancel（复用会话 cancels 表）即杀子进程，无 watchdog（无守护场景，P1 不需要）。
> ⑤⑥迁移兼容照设计：迁移 009 `agent.inference_backend TEXT DEFAULT ''`，读路径空值归一 `eino-adk`（API/前端恒见显式默认值），PUT 老客户端不带字段亦归一，无破坏。
> ⑦新增 `POST /api/inference-backends/reprobe`（force=true 忽略缓存重探测，设计 §8 未单列，实现补充）；Agent 保存校验未知后端 400。
> ⑧chat 侧：KB 召回抽取 `recallKB` 公共段（inprocess / 外部两路共用，避免双路漂移）；外部路径历史拼入提示（最近 10 条），`run.finished` 不带 usage（CLI 无 token 回报）。

## 11. 装配与运行伪代码（主链路，v0.6）

```go
// Runner：一次对话运行
func (r *Runner) Run(ctx context.Context, conv *Conversation, input string, emit Emit) error {
    cfg := r.loadConvConfig(ctx, conv)            // 知识库 / runtime_profile / agent 集合
    var promptCtx string
    if cfg.KB != nil {                            // 知识库（开源检索，§6.9）
        hits, _ := r.kb.Search(ctx, cfg.KB.ID, embed(input), cfg.KB.TopK, cfg.KB.MinScore)
        emit(Event{"retrieval", hits}); promptCtx = render(hits)
    }
    team := r.assemble(ctx, cfg, emit)            // 按 collab_mode 装配（§6.4），
                                                  //   内部：技能注入（§6.12）+ 工具三源合并（§6.8/6.11）
                                                  //   + 按执行后端分发（§6.3）：inprocess 装配 | 沙箱 /run 转发
    stream, err := team.Run(ctx, input, promptCtx)
    if err != nil { return wrapErr(err, emit) }   // 模型/工具/本体 facade 错误 → run.error
    for ev := range stream { translate(ev, emit) } // → §7 SSE
    persistMessagesAndEvents(ctx, conv, stream)
    return nil
}
```

装配细节见 §6.2（单 Agent）、§6.3（后端分发）、§6.4（多 Agent）、§6.12（技能与后端）、§6.10/6.11（本体 facade 与 MCP 合并）。
